# Range Assignment Queries

- **Topic:** #offline-query #reverse-processing #dsu #path-compression #difference-array
- **Updated:** Oct 15, 2026

## 문제

크기 `n`인 배열 `arr`와 `q`개의 쿼리 `(l, r, k)`가 주어진다. 각 쿼리는 **양 끝을 포함하는 구간 `[l, r]`의 모든 값을 `k`로 덮어쓴다.** `n, q <= 10^5`일 때 효율적으로 처리하라.

이 노트에서는 **모든 쿼리가 끝난 뒤의 최종 배열을 반환한다**고 가정한다. 인덱스는 0-based이며 `0 <= l <= r < n`이다. 원래 질문에는 출력 조건이 명시되어 있지 않았다.

```text
arr = [1, 2, 3, 4, 5]
queries = [(1, 3, 7), (2, 4, 9)]

(1, 3, 7) 적용: [1, 7, 7, 7, 5]
(2, 4, 9) 적용: [1, 7, 9, 9, 9]

반환: [1, 7, 9, 9, 9]
```

## 풀이

**쿼리를 거꾸로 처리하면, 각 인덱스를 처음 만났을 때 최종 값이 확정된다. 확정한 인덱스는 DSU의 포인터로 건너뛴다.**

정방향으로 구간을 매번 직접 수정하면 최악 `O(nq)`다. 역순으로 처리하더라도 이미 확정한 칸을 매번 다시 확인하면 같은 문제가 생긴다.

1. `result = arr.copy()`로 시작한다. 어떤 쿼리에도 포함되지 않는 칸은 원래 값을 유지한다.
2. 마지막 쿼리부터 처리한다.
3. `find(l, visited)`로 `l` 이상에서 아직 최종 값이 확정되지 않은 첫 인덱스를 찾는다.
4. 그 인덱스가 `r` 이하면 값을 확정하고 다음 미확정 인덱스로 이동한다.
5. 쿼리가 끝나면 `compression(visited, i)`를 호출해 이번에 거친 모든 확정 인덱스를 다음 미확정 인덱스 `i`로 직접 연결한다.

## parent는 무엇을 저장하는가?

`parent`는 배열의 값이 아니라 **다음 후보 인덱스로 이동하기 위한 화살표**다.

- 실제 배열 인덱스에서 `parent[i] == i`: 아직 최종 값이 확정되지 않은 칸.
- `parent[i] > i`: 이미 확정된 칸이므로 이 화살표를 따라가서 다음 후보를 찾는다.
- `find(i, visited)`: 화살표를 끝까지 따라가서 **`i` 이상인 첫 미확정 인덱스**를 반환한다.
- 인덱스 `n`: 배열 끝을 지났다는 sentinel. `parent[n] == n`이지만 값을 대입할 배열 칸은 아니다.

`parent[i]` 자체가 항상 다음 미확정 인덱스를 직접 가리키는 것은 아니다. 중간에 다른 확정 인덱스를 가리킬 수도 있으므로 `find`로 끝까지 따라간다.

## 코드: find와 compression을 분리

```python
def range_assign(arr, queries):
    n = len(arr)
    result = arr.copy()
    parent = list(range(n + 1))

    def find(i, visited):
        # 여기서는 포인터를 따라가며 방문한 확정 인덱스만 기록한다.
        while parent[i] != i:
            visited.append(i)
            i = parent[i]
        return i

    def compression(visited, next_available):
        # 쿼리가 끝난 뒤 모든 방문 인덱스를 같은 끝점으로 연결한다.
        for i in visited:
            parent[i] = next_available

    for l, r, k in reversed(queries):
        visited = []
        i = find(l, visited)

        while i <= r:
            result[i] = k
            visited.append(i)

            next_i = find(i + 1, visited)
            parent[i] = next_i
            i = next_i

        compression(visited, i)

    return result
```

`visited`에는 **이번에 새로 값을 확정한 인덱스와 `find`가 지나간 기존 확정 인덱스**를 모두 기록한다. 쿼리마다 새 리스트를 만들고, 쿼리 끝에서 한 번 압축한다.

## 예제로 보는 압축 시점

초기 상태에서는 모든 칸이 자신을 가리킨다.

```text
index:   0  1  2  3  4  5
parent:  0  1  2  3  4  5
                        ↑ sentinel
```

역순의 첫 쿼리 `(2, 4, 9)`에서:

```text
인덱스 2 확정: parent[2] = find(3) = 3
인덱스 3 확정: parent[3] = find(4) = 4
인덱스 4 확정: parent[4] = find(5) = 5

쿼리 내부 while 종료 직후:
2 → 3 → 4 → 5
visited = [2, 3, 4]
i = 5
```

**이 시점에는 아직 압축되지 않았다.** 끝에서 다음 호출을 실행한다.

```python
compression([2, 3, 4], 5)
```

```text
parent[2] = 5
parent[3] = 5
parent[4] = 5

2 → 5
3 → 5
4 → 5
```

이제 다음 쿼리 `(1, 3, 7)`을 처리한다.

```text
find(1) = 1 → result[1] = 7
find(2)는 2 → 5로 바로 이동 → next_i = 5
parent[1] = 5
i = 5 > r = 3이므로 종료
마지막 compression도 방문한 인덱스를 5로 연결

최종 배열: [1, 7, 9, 9, 9]
```

## 왜 쿼리 끝에서 한꺼번에 압축해도 되는가?

쿼리 중 `i`는 항상 오른쪽으로 이동한다. `find`가 지나가는 칸은 이미 확정되어 있고, 새로 멈춘 칸은 `r` 이하면 즉시 확정한다.

종료 시 `i`는 `r`보다 큰 첫 미확정 인덱스이거나 sentinel `n`이다. 따라서 `visited`에 기록한 어느 인덱스에서 출발해도 다음 미확정 인덱스는 같은 `i`다. 이들을 모두 `i`로 연결해도 미확정 칸을 건너뛰지 않는다.

각 칸은 역순에서 자신을 포함하는 첫 쿼리의 값을 받는다. 이것이 정방향에서 그 칸을 마지막으로 수정하는 쿼리이므로 최종 값이 맞다.

## 복잡도

- 배열에 값을 대입하는 횟수는 전체 쿼리를 합쳐 **최대 `n`번**이다.
- `find`의 포인터 탐색과 경로 압축까지 포함한 시간은 보수적인 분할 상환 상한으로 **`O((n + q) log(n + 1))`**으로 본다. 한 번의 `find`가 항상 상수 시간인 것은 아니다.
- 추가 공간은 `parent`, `visited`, 반환 배열을 포함해 **`O(n)`**이다. 저장된 입력 쿼리까지 포함하면 `O(n + q)`다.
- `visited`는 매 쿼리 배열 전체를 훑어 만들지 않는다. 실제로 거친 인덱스만 기록한다.

## 틀린 지점 / 헷갈린 지점

- **연결과 압축은 다르다.** `parent[2] = 3`, `parent[3] = 4`로 연결하면 `2 → 3 → 4`라는 체인이 생길 뿐이다. `parent[2] = 4`로 다시 써야 직접 점프한다.
- **압축 전의 탐색은 실제로 체인을 따라간다.** 그 탐색 비용까지 사라지는 것은 아니다. 포인터를 고친 뒤의 탐색에서 이득을 얻는다.
- 이전 코드처럼 `find` 안에서 압축하는 방식도 가능하다. 이 버전은 이해하기 쉽게 탐색과 압축을 분리하고, 쿼리 끝에서 명시적으로 압축한다.
- **쿼리 끝에서 `compression(l)`만 호출하는 코드와는 다르다.** 이 구현은 쿼리에서 거친 모든 인덱스를 `visited`에 저장해 압축한다.
- 값이 `0`이나 음수여도 가능하다. 처리 여부는 값이 아니라 `parent`로 판단한다.
- **최종 배열만 필요할 때 쓰는 offline 풀이**다. 업데이트 사이에 구간 합/최솟값/최댓값을 질의해야 한다면 lazy propagation segment tree를 고려한다.

## Follow-up: 모든 쿼리의 k가 같다면?

모든 쿼리가 같은 값 `k`로 덮어쓰면 **쿼리 순서가 중요하지 않다.** 한 번이라도 쿼리 구간에 포함된 칸만 `k`로 바꾸면 된다. 역순 처리나 DSU 없이 **차분 배열(difference array)**로 해결할 수 있다.

### min(left), max(right)만 사용해도 될까?

**구간들의 합집합에 빈틈이 없을 때만 가능하다.** 떨어진 구간 사이에는 수정하면 안 되는 칸이 있을 수 있다.

```text
arr = [0, 0, 0, 0, 0, 0]
ranges = [(1, 2), (4, 5)], k = 7

실제 바꿀 인덱스: 1, 2, 4, 5
올바른 결과:     [0, 7, 7, 0, 7, 7]

min(left) = 1, max(right) = 5로 한 번에 바꾸면:
                 [0, 7, 7, 7, 7, 7]
                           ↑ 인덱스 3은 쿼리에 포함되지 않음
```

반면 `[1, 2]`와 `[3, 5]`처럼 정수 인덱스에서 서로 이어져 있거나, `[1, 3]`과 `[2, 5]`처럼 겹치면 합집합 전체를 `[1, 5]`로 나타낼 수 있다.

### 차분 배열 풀이

각 구간 `[l, r]`마다 시작점에서 커버 횟수를 1 늘리고, 끝점 바로 다음에서 1 줄인다.

```python
diff[l] += 1
diff[r + 1] -= 1
```

`diff`의 누적합은 현재 인덱스를 덮는 구간의 개수다. 이 값이 양수이면 `k`를 대입하고, 0이면 원래 값을 유지한다.

```python
def range_assign_same_k(arr, ranges, k):
    # ranges는 값 k를 제외한 (l, r) 쌍이다. 양 끝을 포함한다.
    n = len(arr)
    diff = [0] * (n + 1)

    for l, r in ranges:
        diff[l] += 1
        diff[r + 1] -= 1

    result = arr.copy()
    coverage = 0

    for i in range(n):
        coverage += diff[i]
        if coverage > 0:
            result[i] = k

    return result
```

위 반례에서 차분 배열과 누적합은 다음과 같다.

```text
index:     0  1  2   3  4  5   6
diff:      0  1  0  -1  1  0  -1
coverage:  0  1  1   0  1  1   0
              └──┘     └──┘
              수정      수정
```

- **시간: `O(n + q)`**. 쿼리마다 경계 두 곳만 수정하므로 `O(q)`, 마지막 누적합 계산이 `O(n)`이다.
- **추가 공간: `O(n)`**. `diff`는 `n + 1`칸으로 만들어 `r = n - 1`일 때도 `diff[r + 1]`을 기록할 수 있게 한다.
- **겹치는 구간은 coverage가 2 이상일 수 있으므로 `coverage > 0`으로 확인한다.**
- 쿼리가 하나도 없으면 모든 coverage가 0이어서 원래 배열이 반환된다. `k`가 0이나 음수여도 동일하게 동작한다.
- 서로 다른 `k`가 섞이면 커버 횟수만으로 최종 값을 결정할 수 없다. 그때는 앞의 역순 처리 + DSU 풀이를 사용한다.

## 기억할 한 문장

**역순으로 최종 값을 한 번만 확정하고, 쿼리 끝에서 방문한 인덱스들을 다음 미확정 인덱스로 직접 연결한다.**

**모든 k가 같으면 구간의 합집합만 필요하다. 빈틈이 있을 수 있으므로 min/max만 쓰지 말고, 차분 배열의 누적합으로 커버 여부를 구한다.**
