# Earliest Day to Connect Tower Columns

- **Topic:** #bfs #grid #incremental #amortized-analysis
- **Updated:** Oct 15, 2026
- 인터뷰 문제를 정리한 것으로, 별도 LeetCode 번호와 입력 크기 제한은 제공되지 않았다.

## 문제

처음에 비어 있는 `n × m` 격자가 있다. 매일 빈 칸 하나에 타워가 건설된다. 다음 API를 사용할 수 있다.

- `nextTower()`: 그날 건설된 타워의 좌표 `(row, col)`을 반환한다.
- `stopConstruction()`: 이후의 타워 건설을 중단한다.

타워가 있는 칸끼리 **상하좌우**로 이동할 수 있다. 대각선이나 빈 칸으로는 이동할 수 없다. **첫 번째 열의 어느 타워에서 마지막 열의 어느 타워까지 연결되는 최초의 날**에 `stopConstruction()`을 호출하고, 그 날짜를 반환한다. 날짜는 `1`부터 센다.

이 노트에서는 좌표가 1-indexed이고, 모든 좌표가 격자 안에 있으며, 같은 칸이 중복으로 주어지지 않는다고 가정한다. 건설된 타워는 사라지지 않는다. API 종료 규약은 주어지지 않았으므로, 아래 코드는 더 이상 건설할 타워가 없으면 `nextTower()`가 `None`을 반환한다고 가정한다. 연결 없이 종료되면 `-1`을 반환한다.

### 예시

```text
n = 3, m = 3
건설 순서 = [(2,1), (1,2), (2,3), (2,2)]
결과 = 4

3일 후:         4일 후:
. T .           . T .
T . T           T T T
. . .           . . .
```

3일째까지는 대각선으로만 닿으므로 연결되지 않는다. 4일째 `(2,2)`가 건설되면 `(2,1) → (2,2) → (2,3)` 경로가 생긴다.

## 풀이: 도달 가능한 영역을 유지하는 BFS

매일 BFS를 처음부터 다시 실행할 필요는 없다. **타워가 추가되기만 하므로, 첫 번째 열에서 한 번 도달 가능해진 타워는 계속 도달 가능하다.** 이 정보를 날짜가 바뀌어도 유지한다.

- `built`: 지금까지 건설된 모든 타워 좌표.
- `reachable`: 첫 번째 열의 타워에서 출발해 도달할 수 있는 타워 좌표.

매일 다음 순서로 처리한다.

1. 새 타워를 `built`에 추가한다.
2. 새 타워가 첫 번째 열에 있거나, 상하좌우 중 하나가 `reachable`에 있으면 새 타워도 도달 가능하다.
3. 이 조건을 만족하지 않으면 그날의 처리를 마친다. 타워는 `built`에 남겨 두고, 이후에 연결될 때 탐색한다.
4. 조건을 만족하면 새 타워를 `reachable`에 추가하고 BFS 큐에 넣는다.
5. BFS는 `built`에 있으면서 아직 `reachable`에 없는 이웃으로 확장한다. **큐에 넣을 때** `reachable`에도 추가한다.
6. 마지막 열의 타워에 도달하면 건설을 중단하고 현재 날짜를 반환한다.

새 타워가 이전부터 존재하던 고립된 타워 무리를 연결할 수도 있다. 따라서 새 타워 하나만 검사하는 것으로 끝내지 않고, 그 타워를 통해 새로 도달 가능해진 영역 전체로 BFS를 확장해야 한다.

## 코드

```python
from collections import deque


def earliest_day(n, m, nextTower, stopConstruction):
    built = set()
    reachable = set()
    directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]
    day = 0

    while True:
        cell = nextTower()  # 더 이상 타워가 없으면 None을 반환한다고 가정.
        if cell is None:
            return -1

        day += 1
        r, c = cell  # 1-indexed 좌표.
        built.add((r, c))

        if c != 1 and not any(
            (r + dr, c + dc) in reachable
            for dr, dc in directions
        ):
            continue

        queue = deque([(r, c)])
        reachable.add((r, c))

        while queue:
            row, col = queue.popleft()

            if col == m:
                stopConstruction()
                return day

            for dr, dc in directions:
                neighbor = (row + dr, col + dc)

                if neighbor in built and neighbor not in reachable:
                    reachable.add(neighbor)
                    queue.append(neighbor)
```

`built`에는 유효한 격자 좌표만 있으므로 이웃이 격자 밖이면 집합 조회에서 자동으로 제외된다. 이 코드에서 `n`은 격자 크기를 나타내는 매개변수이며, 별도의 배열 초기화나 경계 검사에는 사용하지 않는다.

## 왜 정답을 찾는가?

하루의 탐색이 끝날 때 `reachable`은 첫 번째 열에서 도달 가능한 타워 전체를 담는다.

- 새 타워가 첫 번째 열에도 없고 기존 `reachable`과도 닿지 않으면, 그 타워를 통해 첫 번째 열에서 출발하는 새 경로가 생길 수 없다. 다른 타워 사이의 연결은 바뀌지 않았으므로 기존 상태를 유지해도 된다.
- 새 타워가 첫 번째 열에 있거나 기존 `reachable`과 닿으면 도달 가능하다. BFS가 그 타워와 연결된 기존 타워들을 모두 탐색하므로 새로 도달 가능한 영역을 빠짐없이 추가한다.

따라서 마지막 열의 타워를 발견하는 것은 양 끝 열을 연결하는 경로가 존재한다는 뜻이다. 매일 추가 직후 확인하므로 처음 발견한 날짜가 가장 이른 날짜다.

## 복잡도: 왜 O(d²)가 아니라 O(d)인가?

`d`는 중단 또는 API 종료까지 처리한 타워 수다. 집합 조회와 추가는 평균 `O(1)`, API 호출 자체는 `O(1)`로 가정한다.

**매일 방문 집합을 비우고 전체 BFS를 다시 하면**, 최악에는 다음처럼 같은 타워를 반복 탐색한다.

```text
1일: 1개 탐색
2일: 2개 탐색
...
d일: d개 탐색

합계 = 1 + 2 + ... + d = O(d²)
```

하지만 이 코드의 `reachable`은 `while True` 바깥에서 만들어지고, 매일 초기화하지 않는다.

```python
if neighbor in built and neighbor not in reachable:
    reachable.add(neighbor)  # enqueue 전에 방문 처리.
    queue.append(neighbor)
```

- 새 타워마다 도달 가능 여부를 확인하는 이웃 검사는 최대 4번이다. 전체 `O(d)`다.
- 각 타워는 전체 실행 동안 BFS 큐에 **최대 한 번** 들어간다. 큐에서 꺼낼 때 이웃을 4번 확인하므로 BFS 전체도 `O(d)`다.
- 따라서 전체 시간은 평균 **`O(d)`**, 추가 공간은 **`O(d)`**다. `n × m` 배열을 미리 만들지 않으므로 별도의 `O(nm)` 초기화 비용도 없다.

어느 하루에는 큰 고립 영역이 한꺼번에 연결되어 BFS에 `O(d)`가 걸릴 수 있다. 하지만 그날 탐색한 타워는 이후에 다시 큐에 들어가지 않는다. **하루의 최대 비용을 모든 날에 곱하면, 실제로 반복되지 않는 탐색까지 중복해서 세게 된다.**

## 헷갈린 지점 / 기억할 것

- 반복문 안에 BFS가 있다고 바로 `O(d²)`는 아니다. 전체 실행 동안 각 타워가 큐에 들어가는 횟수를 센다.
- `reachable`은 모든 방문 기록이 아니라 **첫 번째 열에서 도달 가능한 타워**의 집합이다. `built`와 구분한다.
- 아직 도달 불가능한 타워도 `built`에는 남겨야 나중에 연결되었을 때 BFS로 탐색할 수 있다.
- 방문 처리는 `popleft()`할 때가 아니라 큐에 넣을 때 한다. 여러 이웃이 같은 좌표를 중복으로 넣는 것을 막는다.
- 타워가 추가되기만 한다는 조건이 핵심이다. 타워가 제거될 수도 있다면 기존 `reachable`이 유효하지 않을 수 있다.
- `m == 1`이면 첫 번째 열과 마지막 열이 같으므로 첫 타워가 건설된 날 바로 중단한다.
- Union-Find 없이도, 한쪽 경계에서의 도달 가능성만 유지하면 이 문제를 해결할 수 있다.
