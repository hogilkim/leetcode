# Longest Substring With Increasing Endpoints

- **Topic:** #string #greedy #linear-scan
- **Updated:** Oct 15, 2026

## 문제

영어 소문자로만 이루어진 문자열 `s`가 주어진다. **첫 문자가 마지막 문자보다 사전순으로 작은 연속 부분 문자열의 최대 길이**를 반환한다. 조건을 만족하는 부분 문자열이 없으면 `0`을 반환한다.

인덱스로 표현하면 `i < j`이고 `s[i] < s[j]`인 구간 `s[i:j + 1]` 중 `j - i + 1`의 최댓값을 구하는 문제이다.

- 문자열 길이: `1 <= len(s) <= 10^5`
- 문자는 `'a'`부터 `'z'`까지 26종류이다.
- **양 끝 문자만 비교한다.** 중간 문자들은 정렬되어 있을 필요가 없다.
- 같은 문자는 허용하지 않는다. `'a' < 'a'`는 거짓이므로 길이 1인 부분 문자열도 유효하지 않다.

```text
입력: s = "dbabcb"
출력: 4
설명: s[2:6] = "abcb"에서 'a' < 'b'이다.
      s[1:5] = "babc"도 'b' < 'c'이므로 길이 4이다.

입력: s = "abca"
출력: 3
설명: "abc"에서 'a' < 'c'이다.

입력: s = "cba"
출력: 0
```

## 처음 생각한 접근: 문자열의 마지막 문자와만 비교하기

각 문자를 **전체 문자열의 마지막 문자**와 비교하고, 더 작은 문자가 처음 나오는 위치부터 끝까지의 길이를 구하면 되지 않을까?

이 방법은 **전체 문자열의 마지막 위치에서 끝나는 부분 문자열**만 확인한다. 최적 구간이 더 앞에서 끝나는 경우를 놓친다.

반례는 `s = "abca"`이다.

```text
인덱스: 0 1 2 3
문자:   a b c a
```

마지막 문자는 `'a'`이고, 이보다 작은 문자가 없으므로 위 방법은 `0`을 반환한다. 하지만 `s[0:3] = "abc"`는 `'a' < 'c'`이므로 정답은 `3`이다.

`"dbabcb"`에서는 최적 구간 중 하나인 `"abcb"`가 우연히 마지막 위치에서 끝나므로 이 접근으로도 정답이 나온다. **주어진 예시에서 맞는 것만으로 일반적으로 맞는 방법이라고 판단하면 안 된다.**

## 풀이: 문자별 첫 등장·마지막 등장 + 알파벳 순회

시작 문자가 `'a'`, 끝 문자가 `'b'`처럼 두 문자의 종류가 정해졌다면, 가장 긴 구간을 만들려면 **시작 문자는 최대한 왼쪽, 끝 문자는 최대한 오른쪽**에서 선택해야 한다.

1. 문자열을 한 번 순회하여 각 문자의 첫 등장 위치 `first`와 마지막 등장 위치 `last`를 기록한다.
2. 끝 문자 후보 `c`를 `'a'`부터 `'z'`까지 순회한다.
3. `earliest_start`에는 **현재 문자 `c`보다 작은 모든 문자의 첫 등장 위치 중 최솟값**을 유지한다.
4. `earliest_start < last[c]`이면 유효한 구간이므로 `last[c] - earliest_start + 1`로 정답을 갱신한다.
5. 현재 문자의 `first[c]`를 `earliest_start`에 반영하고 다음 문자로 넘어간다.

없는 문자의 첫 위치는 `n`, 마지막 위치는 `-1`로 두면 유효성 검사에서 자연스럽게 제외된다.

```python
class Solution:
    def maxLength(self, s: str) -> int:
        n = len(s)
        first = [n] * 26
        last = [-1] * 26

        for i, ch in enumerate(s):
            c = ord(ch) - ord('a')
            first[c] = min(first[c], i)
            last[c] = i

        answer = 0
        earliest_start = n

        for c in range(26):
            # 현재 c보다 작은 문자들만 시작 후보에 포함되어 있다.
            if earliest_start < last[c]:
                answer = max(answer, last[c] - earliest_start + 1)

            # 현재 c는 다음번의 더 큰 끝 문자부터 시작 후보가 된다.
            earliest_start = min(earliest_start, first[c])

        return answer
```

### 순회 예시: `"dbabcb"`

```text
인덱스: 0 1 2 3 4 5
문자:   d b a b c b
```

| 끝 문자 | `first` | `last` | 비교 직전 `earliest_start` | 후보 길이 |
| --- | --- | --- | --- | --- |
| a | 2 | 2 | 6: 더 작은 문자 없음 | 없음 |
| b | 1 | 5 | 2: a의 첫 위치 | 5 - 2 + 1 = 4 |
| c | 4 | 4 | 1: a, b 중 가장 이른 위치 | 4 - 1 + 1 = 4 |
| d | 0 | 0 | 1: a, b, c 중 가장 이른 위치 | 시작 위치가 끝보다 뒤이므로 제외 |

최종 정답은 `4`이다. 등장하지 않는 나머지 문자들은 `last[c] = -1`이므로 제외된다.

## 왜 맞는가?

끝 문자의 종류를 `c`로 고정하자. 어떤 유효 구간 `[i, j]`가 있다면 `s[i] < c`이고, `earliest_start <= i`, `last[c] >= j`이다. 따라서 알고리즘이 선택한 구간은 그 구간보다 짧지 않다.

또한 `earliest_start`의 문자는 `c`보다 엄격히 작고, 시작 위치가 끝 위치보다 앞인지도 확인하므로 선택한 구간은 항상 유효하다. 모든 끝 문자 종류를 확인하므로 전체 최댓값을 구할 수 있다.

## 복잡도

- **시간: `O(n + 26) = O(n)`**. 문자열을 한 번 순회하고, 알파벳 26개를 한 번 순회한다.
- **추가 공간: `O(26) = O(1)`**. 고정 크기 배열 두 개만 사용한다.

## 기억할 것 / 헷갈린 지점

- 전체 문자열의 마지막 문자로 끝점을 고정하면 앞에서 끝나는 최적 구간을 놓친다. 반례: `"abca"` → `3`.
- `earliest_start`는 **사전순으로 가장 작은 문자**의 위치가 아니라, **현재 끝 문자보다 작은 문자들 중 가장 이른 인덱스**이다.
- **정답을 비교한 뒤 `earliest_start`를 갱신한다.** 순서를 바꾸면 같은 문자를 양 끝에 허용하게 된다. 예: `"aa"`의 정답은 `0`이다.
- 문자 크기 조건 `s[i] < s[j]`와 인덱스 순서 조건 `i < j`를 모두 만족해야 한다.
- 부분 문자열의 길이는 `j - i + 1`이다. [962. Maximum Width Ramp](../오답노트/962.%20Maximum%20Width%20Ramp.md)의 너비 `j - i`와 구분한다. 이 문제의 문자 비교는 `<`, Ramp의 값 비교는 `<=`이다.
- **기억할 한 문장: 끝 문자마다 마지막 위치를 고르고, 그보다 작은 문자들의 가장 이른 위치와 연결한다.**
