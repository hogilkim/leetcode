## 문제

출발 공항 `origin`, 목적지 공항 `destination`, 항공편 목록 `flights`가 주어진다. 각 항공편은 다음 정보를 가진다.

```text
(출발 공항, 도착 공항, 출발 시각, 도착 시각)
```

패키지는 시각 `0`에 출발 공항에 도착해 있다. 항공편을 여러 번 이용하여 목적지에 도달할 수 있으면 `True`, 불가능하면 `False`를 반환한다.

- 공항에 도착한 뒤 기다릴 수 있다.
- **항공편 출발 시각 >= 패키지의 현재 공항 도착 시각**이어야 탑승할 수 있다.
- 두 시각이 같아도 환승할 수 있다. 추가 환승 시간은 없다.
- 모든 시각은 공통된 기준이며, 각 항공편은 `출발 시각 <= 도착 시각`이라고 가정한다.
- 출발 공항과 목적지가 같으면 이동 없이 `True`다.

### 예시

```text
origin = "NYC", destination = "SFO"

NYC → LAX: 출발 0, 도착 4
LAX → SFO: 출발 5, 도착 7
결과: True
```

LAX에 시각 4에 도착하고, 시각 5까지 기다린 뒤 다음 항공편을 탄다.

```text
NYC → LAX: 출발 0, 도착 4
LAX → SFO: 출발 3, 도착 5
결과: False
```

LAX에 도착했을 때 SFO행 항공편은 이미 출발했다.

## 핵심: `earliest`는 무엇인가?

`earliest[airport]`는 **지금까지 발견한 경로 중, 그 공항에 가장 일찍 도착하는 시각**이다. 아직 최종 확정되지 않은 값일 수 있으며, 더 빠른 경로를 찾으면 갱신한다.

```python
earliest = {
    "NYC": 0,
    "LAX": 4,
    "ORD": 3,
}
```

이 딕셔너리는 NYC에는 시각 0, LAX에는 시각 4, ORD에는 시각 3에 도착하는 경로를 찾았다는 뜻이다. 하나의 이동 경로를 표현하는 것은 아니다. **공항마다 별도의 기록**이 있다.

LAX에 도착하는 다른 경로를 찾았다고 하자.

| 새 경로의 LAX 도착 시각 | 처리 | 이유 |
|---|---|---|
| 6 | 무시 | 시각 4에 도착해 기다리면, 시각 6에 도착해서 탈 수 있는 항공편을 모두 탈 수 있다. |
| 2 | `earliest["LAX"] = 2`로 갱신 | 시각 2나 3에 출발하는 항공편도 탈 수 있게 된다. |
| 4 | 무시 | 같은 공항, 같은 도착 시각이므로 이후 가능한 이동이 같다. |

**일찍 도착하는 것이 유리하다는 비교는 같은 공항에 도착하는 경로 사이의 비교다.** LAX에 시각 2에 도착하는 경로와 ORD에 시각 3에 도착하는 경로는 둘 다 보관한다.

## 풀이: 다익스트라 + 최소 힙

- `graph[airport]`: 해당 공항에서 출발하는 항공편 목록.
- `earliest[airport]`: 지금까지 찾은 해당 공항의 가장 빠른 도착 시각.
- `heap`: 앞으로 탐색할 `(도착 시각, 공항)` 후보들. 가장 작은 시각부터 꺼낸다.

1. `earliest = {origin: 0}`, `heap = [(0, origin)]`으로 시작한다.
2. 힙에서 후보 `(time, airport)`를 꺼낸다.
3. `time != earliest[airport]`이면 더 빠른 경로가 이미 발견된 오래된 후보이므로 건너뛴다.
4. 현재 공항이 목적지면 `True`를 반환한다.
5. 현재 공항에서 출발하는 모든 항공편을 확인한다.
   - `departure < time`이면 이미 떠난 항공편이므로 건너뛴다.
   - 다음 공항에 기존 기록보다 일찍 도착하면 기록을 갱신하고 힙에 넣는다.
6. 힙이 빌 때까지 목적지를 찾지 못하면 `False`다.

항공편의 시각은 절대 시각이다. 다음 도착 시각은 항공편에 적힌 `arrival`이며, `time + arrival`이 아니다.

## 코드

```python
from collections import defaultdict
import heapq


def can_reach(origin, destination, flights):
    graph = defaultdict(list)
    for src, dst, departure, arrival in flights:
        graph[src].append((dst, departure, arrival))

    earliest = {origin: 0}
    heap = [(0, origin)]

    while heap:
        time, airport = heapq.heappop(heap)

        # 더 빠른 경로가 발견되기 전에 힙에 넣었던 오래된 후보.
        if time != earliest[airport]:
            continue

        if airport == destination:
            return True

        for next_airport, departure, arrival in graph[airport]:
            if departure < time:
                continue

            if arrival < earliest.get(next_airport, float("inf")):
                earliest[next_airport] = arrival
                heapq.heappush(heap, (arrival, next_airport))

    return False
```

### 갱신 조건 읽기

```python
if arrival < earliest.get(next_airport, float("inf")):
```

“이번 항공편으로 다음 공항에 도착하는 시각이, 지금까지 찾은 그 공항의 도착 시각보다 빠른가?”라는 뜻이다.

아직 도착한 적이 없는 공항은 기록이 없으므로 `float("inf")`, 즉 무한대로 취급한다. 처음 발견한 유효한 도착 시각은 무한대보다 작으므로 기록된다.

### 오래된 힙 후보를 건너뛰는 이유

처음에 LAX에 시각 10에 도착하는 경로를 찾아 `(10, "LAX")`를 힙에 넣었다고 하자. 이후 ORD를 거쳐 LAX에 시각 4에 도착하는 경로를 발견하면 다음처럼 된다.

```text
earliest["LAX"] = 4
힙에는 (4, "LAX")와 (10, "LAX")가 둘 다 남아 있을 수 있다.
```

`(4, "LAX")`에서 탈 수 있는 항공편을 이미 확인하므로, 나중에 `(10, "LAX")`를 꺼냈을 때는 다시 탐색할 필요가 없다. 힙에서 예전 항목을 직접 삭제하지 않고, 꺼낼 때 기록과 비교해서 건너뛴다.

## 헷갈린 지점: 일찍 도착한 곳이 막다른 길이면?

```text
NYC → LAX: 출발 0, 도착 2  ← 이후 항공편 없음
NYC → ORD: 출발 0, 도착 3
ORD → SFO: 출발 4, 도착 6
```

NYC의 항공편을 처리하면 두 후보가 모두 저장된다.

```text
earliest = {"NYC": 0, "LAX": 2, "ORD": 3}
heap = [(2, "LAX"), (3, "ORD")]
```

1. `(2, "LAX")`를 먼저 꺼낸다. 다음 항공편이 없어 아무것도 추가하지 않는다.
2. **힙에는 `(3, "ORD")`가 그대로 남아 있다.** ORD를 꺼내 SFO행 항공편을 확인한다.
3. `4 >= 3`이므로 탑승 가능하다. `earliest["SFO"] = 6`으로 기록하고 `(6, "SFO")`를 넣는다.
4. SFO를 꺼내면 `True`를 반환한다.

힙에서 꺼내는 순서는 **탐색 순서**다. 패키지가 실제로 `NYC → LAX → ORD → SFO`로 이동한다는 뜻이 아니다. 성공한 실제 경로는 `NYC → ORD → SFO`다.

한 후보가 막다른 길이어도 다른 후보는 계속 탐색한다. **전체 힙이 비었을 때만** 도달 불가능하다고 판단한다.

## 왜 정답을 찾는가?

같은 공항에 `t1 <= t2`에 도착하는 두 경로가 있다면, `t2` 이후에 출발하는 항공편은 `t1`에 도착한 패키지도 기다렸다가 탈 수 있다. 따라서 늦게 도착하는 경로를 버려도 가능한 환승을 잃지 않는다.

또한 유효한 항공편은 `현재 도착 시각 <= 출발 시각 <= 다음 도착 시각`을 만족한다. 힙에서 가장 작은 시각을 꺼냈다면, 그보다 늦은 후보를 거쳐 해당 공항에 더 일찍 도착할 수는 없다. 따라서 오래된 항목이 아닌 후보를 꺼낼 때 그 공항의 최단 도착 시각이 확정되며, 해당 공항의 항공편 목록을 한 번만 탐색하면 된다.

가능한 모든 항공편을 확인하고, 같은 공항의 덜 유리한 도착만 제외하므로 유효한 경로가 있다면 목적지를 발견한다.

## 복잡도

`F`는 항공편 수, `A`는 공항 수다.

- **시간: `O(A + F log(F + 1))`**. 각 공항의 항공편 목록은 한 번 탐색하고, 힙 삽입은 항공편당 최대 한 번이다. 중복 후보를 포함한 힙 크기는 `O(F + 1)`이다.
- **공간: `O(A + F)`**. 항공편 그래프, 공항별 기록, 힙을 저장한다.

## 기억할 것

- `earliest`는 **공항별 가장 빠른 도착 시각**이다. 전체에서 공항 하나만 고르는 값이 아니다.
- 힙은 여러 가능한 경로의 후보를 동시에 보관한다. 막다른 후보 하나로 전체 탐색이 실패하지 않는다.
- 탑승 조건은 `departure >= time`이다. 같은 시각의 환승도 허용한다.
- 힙에 처음 넣었을 때 방문을 확정하면 안 된다. 나중에 같은 공항으로 더 빠르게 도착하는 경로를 발견할 수 있다.
- 이미 시각 4에 도착할 수 있다면 시각 6에 도착하는 경로는 추가하지 않는다. 기다리면 되기 때문이다.
- 도착 시각이 같으면 갱신하지 않는다. 엄격한 `<` 비교로 같은 시각의 사이클도 불필요하게 반복하지 않는다.
- 항공편이 없으면 `origin == destination`인 경우만 `True`다.
