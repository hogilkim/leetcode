# Longest Path in a DAG

- **Topic:** #graph #dag #dfs #memoization #dp #topological-sort
- **Updated:** Oct 15, 2026
- 대화에서 제시된 문제이며 별도 LeetCode 번호와 입력 크기 제한은 제공되지 않았다.

## 문제

노드가 `0`부터 `n - 1`까지 있는 **방향 비순환 그래프(DAG)**와 간선 배열 `edges`가 주어진다. `edges[i] = [u, v]`는 `u → v` 방향으로 이동할 수 있다는 뜻이다.

**어떤 노드에서 출발해 어떤 노드에서 끝나든, 가능한 모든 방향 경로 중 가장 긴 경로의 길이**를 반환한다.

- DAG는 방향을 따라 이동했을 때 사이클이 없는 그래프다.
- 이 노트에서는 가중치가 없고, 경로의 길이는 **간선 수**로 센다. 간선 하나의 거리는 `1`이다.
- 시작점과 도착점은 지정되지 않는다. 서로 연결되지 않은 부분도 모두 고려한다.
- 간선이 없으면 답은 `0`이다. 노드 하나만 있는 경로의 길이도 `0`이다.
- 두 노드 사이의 최단 거리를 먼저 구하는 문제가 아니다. 가능한 경로 자체의 길이를 최대화한다.

### 예시

```text
n = 5
edges = [[0,1], [0,2], [1,3], [2,3], [3,4]]

0 → 1 → 3 → 4
 ↘ 2 ↗

출력: 3
```

`0 → 1 → 3 → 4`와 `0 → 2 → 3 → 4`는 각각 간선이 세 개이므로 길이가 `3`이다. 노드는 네 개지만 반환값은 `3`이다.

## 풀이: DFS + 수동 메모이제이션

`dfs(u)`를 **노드 `u`에서 출발하는 가장 긴 경로의 간선 수**로 정의한다. `u`에 도착하는 경로의 길이가 아니라, `u`부터 앞으로 갈 수 있는 길이다.

```text
dfs(u) = max(1 + dfs(v))  for every edge u → v
다음 노드가 없으면 dfs(u) = 0
```

`u → v`를 선택하면 간선 하나를 사용하고, 이후에는 `v`에서 출발하는 최장 경로를 이어 붙일 수 있다. 모든 다음 노드에 대해 계산한 값 중 최댓값을 선택한다.

1. 간선 목록으로 방향 인접 리스트를 만든다.
2. `memo[u]`가 있으면 이미 계산한 `dfs(u)`를 반환한다.
3. 없으면 모든 이웃 `v`에 대해 `1 + dfs(v)`의 최댓값을 구한다.
4. 계산을 마친 뒤 `memo[u]`에 저장한다.
5. 시작점이 자유로우므로 모든 노드의 `dfs(u)` 중 최댓값을 반환한다.

## 코드

`@cache` 대신 일반 딕셔너리로 캐시를 직접 구현한다.

```python
from typing import List


class Solution:
    def longestPath(self, n: int, edges: List[List[int]]) -> int:
        graph = [[] for _ in range(n)]
        for u, v in edges:
            graph[u].append(v)

        memo = {}

        def dfs(u):
            if u in memo:
                return memo[u]

            longest = 0
            for v in graph[u]:
                longest = max(longest, 1 + dfs(v))

            memo[u] = longest
            return longest

        return max((dfs(u) for u in range(n)), default=0)
```

### 예시 추적

앞의 그래프에서 `dfs(0)`을 호출하고 `1`을 먼저 탐색한다고 하자.

```text
dfs(0) → dfs(1) → dfs(3) → dfs(4)

dfs(4) = 0  → memo[4] = 0
dfs(3) = 1  → memo[3] = 1
dfs(1) = 2  → memo[1] = 2

이후 0의 다른 이웃인 2를 탐색:
dfs(2) → dfs(3)
         이미 memo[3] = 1이므로 바로 반환
dfs(2) = 2  → memo[2] = 2

dfs(0) = max(1 + 2, 1 + 2) = 3
```

모든 노드를 시작점으로 확인한 결과는 `[3, 2, 2, 1, 0]`이고, 최댓값 `3`을 반환한다. 바깥 반복문이 나머지 노드를 호출할 때도 저장된 값을 재사용한다.

## 왜 `visited`가 필요 없는가?

이 문제에서는 **DAG라는 조건과 `memo`가 서로 다른 역할**을 한다.

| 구분 | 역할 |
|---|---|
| DAG 조건 | 현재 재귀 경로의 노드로 돌아오는 사이클이 없으므로 재귀가 종료된다. |
| `memo` | 계산을 끝낸 노드의 답을 재사용하여 공유되는 뒷부분을 반복 계산하지 않는다. |

`0 → 1 → 3`과 `0 → 2 → 3`처럼 여러 경로가 같은 노드 `3`에 도달할 수는 있다. 하지만 `3`부터 갈 수 있는 최장 길이는 어느 경로로 들어왔든 같다. DAG에서는 이후 경로가 앞서 방문한 노드로 되돌아가면 사이클이 되므로, 방문 경로를 별도 상태로 저장할 필요가 없다.

따라서 일반 탐색처럼 “이미 방문한 노드라면 건너뛴다”로 처리하지 않고, **이미 계산한 노드라면 그 최장 길이를 반환**해야 한다. 다른 가지도 그 값을 이용해야 하기 때문이다.

### 사이클이 있다면?

```text
0 → 1 → 0
```

`memo[u]`는 자식 호출을 모두 마친 **후** 저장한다. 위 그래프에서는 `dfs(0) → dfs(1) → dfs(0) → ...`가 반복되며 어느 값도 저장하지 못한다. **메모이제이션 자체가 사이클을 막아 주는 것은 아니다.**

DAG가 보장되지 않는다면 현재 재귀 스택에 있는 노드를 추적해 사이클을 탐지해야 한다. 사이클을 발견했다고 이 점화식으로 일반 그래프의 최장 단순 경로까지 해결되는 것은 아니다.

## 왜 정답을 찾는가?

다음 노드가 없는 노드에서 시작하는 최장 경로는 간선이 없으므로 `0`이다. 그 외의 노드 `u`에서 이동하는 경로는 반드시 어떤 첫 간선 `u → v`를 선택한다. 이후 최장 길이가 `dfs(v)`라면 그 간선을 선택했을 때의 최장 길이는 `1 + dfs(v)`다.

DFS는 모든 다음 노드의 답을 구한 뒤 최댓값을 저장한다. DAG에서는 이 의존 관계에 사이클이 없으므로 각 노드의 답을 올바르게 계산할 수 있다. 마지막으로 모든 시작점의 답을 비교하므로 그래프 전체의 최장 경로를 얻는다.

## 복잡도

`V = n`, `E = len(edges)`다. 딕셔너리 조회와 저장은 평균 `O(1)`로 본다.

- **시간: `O(V + E)`**. 각 노드의 이웃 목록은 한 번만 계산하고 각 간선도 한 번씩 확인한다. 캐시가 없으면 여러 경로가 공유하는 뒷부분을 반복 탐색하여 지수 시간이 걸릴 수 있다.
- **공간: `O(V + E)`**. 인접 리스트가 `O(V + E)`, 캐시와 재귀 스택이 각각 `O(V)`다.

긴 일자형 DAG에서는 재귀 깊이가 `O(V)`이므로 Python의 재귀 제한에 걸릴 수 있다. 이런 경우 위상 정렬을 이용하면 재귀 없이 계산할 수 있다.

## 대안: 위상 정렬 + DP

DFS와 다르게 `dist[v]`를 **노드 `v`에서 끝나는 최장 경로의 길이**로 정의할 수도 있다.

모든 값을 `0`으로 초기화하고 진입 차수가 `0`인 노드들을 큐에 넣는다. 위상 순서대로 노드 `u`를 꺼내 간선 `u → v`마다 아래처럼 갱신한다.

```python
dist[v] = max(dist[v], dist[u] + 1)
```

간선을 처리할 때 `v`의 진입 차수를 줄이고, `0`이 되면 큐에 넣는다. 모든 선행 노드의 갱신이 끝난 뒤 `v`를 처리하므로 답이 확정된 순서로 계산한다. 마지막에 `max(dist, default=0)`을 반환한다. 시간과 공간은 동일하게 `O(V + E)`다.

## 헷갈린 지점 / 기억할 것

- **DFS도 가능하다.** DAG의 최장 경로는 DFS + 메모이제이션으로 선형 시간에 구할 수 있다.
- `dfs(u)`는 **u에서 시작**, 위상 정렬 풀이의 `dist[u]`는 **u에서 끝나는** 최장 길이다. 점화식의 방향을 섞지 않는다.
- 길이는 노드 수가 아닌 **간선 수**다. 막다른 노드의 답은 `0`이다.
- 수동 캐시는 `if u in memo`로 확인한다. `if memo.get(u)`는 유효한 캐시 값 `0`을 놓친다.
- 결과는 모든 이웃을 확인한 **후** 캐시에 저장한다.
- 시작점이 지정되지 않았으므로 모든 노드에서 시작하는 답을 비교한다. 노드 `0`만 탐색하면 다른 부분의 최장 경로를 놓칠 수 있다.
- **별도 `visited` 없이 가능한 이유는 DAG 보장 + 캐시 재사용이다.** 일반 그래프에 그대로 적용하면 안 된다.
