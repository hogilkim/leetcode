# Remove Bad Pairs

- **Topic:** #stack #string #unit-testing
- **Updated:** Oct 15, 2026
- 처음 선택한 스택 접근은 올바르다. 핵심은 연쇄 제거를 처리하는 이유와 테스트 설계 기준을 설명하는 것이다.

## 문제

문자열에서 **같은 영문자이지만 대소문자가 다른 인접한 두 문자**를 bad pair라고 한다. Bad pair를 반복해서 제거하고, 더 이상 제거할 쌍이 없는 문자열을 반환한다. 남은 문자의 순서는 유지한다.

- `"xX"`, `"Xx"`: bad pair이므로 제거한다.
- `"xx"`, `"XX"`: 대소문자가 같으므로 유지한다.
- `"xY"`: 서로 다른 글자이므로 유지한다.
- 빈 문자열은 `""`를 반환한다.

```text
입력: "abxXw"
출력: "abw"

입력: "abBA"
과정: "abBA" → "aA" → ""
출력: ""
```

두 번째 예시처럼 **제거 후 새로 인접하게 된 문자도 다시 제거 대상이 된다.** 아래 풀이의 문자 비교는 영문 대소문자를 기준으로 한다.

## 풀이: 스택에 지금까지 처리한 결과를 저장한다

문자열을 왼쪽에서 오른쪽으로 읽는다. `stack`에는 지금까지 읽은 부분에서 bad pair를 모두 제거한 결과를 저장한다.

1. 스택이 비어 있지 않으면 마지막 문자와 현재 문자를 비교한다.
2. 두 문자가 서로 다르고, 소문자로 바꾸면 같다면 bad pair이다. 스택의 마지막 문자를 `pop()`하고 현재 문자도 넣지 않는다.
3. 그 외에는 현재 문자를 `append()`한다.
4. 마지막에 `"".join(stack)`으로 결과를 반환한다.

```python
def remove_bad_pairs(s: str) -> str:
    stack = []

    for char in s:
        if (
            stack
            and stack[-1] != char
            and stack[-1].lower() == char.lower()
        ):
            stack.pop()
        else:
            stack.append(char)

    return "".join(stack)
```

`stack[-1] != char`가 없으면 `"aa"`도 잘못 제거한다. `lower()` 비교가 없으면 `"aB"`처럼 서로 다른 문자도 제거할 수 있다. 두 조건이 모두 필요하다.

### 연쇄 제거 예시: `"abBAc"`

| 읽은 문자 | 처리 | 스택 |
| --- | --- | --- |
| `a` | 비어 있으므로 추가 | `[a]` |
| `b` | `a`와 bad pair가 아니므로 추가 | `[a, b]` |
| `B` | `bB` 제거 | `[a]` |
| `A` | 이제 맨 위인 `a`와 `aA` 제거 | `[]` |
| `c` | 비어 있으므로 추가 | `[c]` |

결과는 `"c"`이다. `pop()`하면 이전 문자가 자동으로 맨 위에 드러나므로, 원본 문자열을 처음부터 다시 탐색하지 않아도 된다.

## 왜 맨 위만 비교하면 되는가?

**매 반복이 끝날 때 스택 내부에는 bad pair가 없다**는 불변식을 유지한다.

- 처음에는 빈 스택이므로 성립한다.
- 현재 문자를 추가할 때 새 bad pair가 생길 수 있는 곳은 스택의 마지막 문자와 현재 문자 사이뿐이다.
- 둘이 bad pair라면 둘 다 제거한다. 기존 스택의 끝 문자 하나만 없어지므로, 남은 스택 내부에 새로운 인접 관계가 생기지 않는다.
- bad pair가 아니라면 추가해도 스택 내부에 bad pair가 없다.

따라서 모든 문자를 처리한 뒤의 스택이 정답이다. 현재 문자도 함께 제거되므로 `pop()` 직후 같은 현재 문자를 다시 비교하는 `while`은 필요 없다.

## 복잡도

문자열 길이를 `n`이라고 하면:

- **시간: O(n)**. 각 문자는 최대 한 번 추가되고 한 번 제거된다. 마지막 `join`도 O(n)이다.
- **공간: O(n)**. 제거할 쌍이 없으면 모든 문자가 스택에 남는다.

문자열을 잘라 붙이며 처음부터 반복 탐색하는 방식은 최악 O(n²)이 될 수 있다.

## Follow-up: 기능을 설계한다면 어떤 단위 테스트가 필요한가?

예시 몇 개를 임의로 고르기보다 **입력 경계, 제거 조건, 제거 위치, 연쇄 동작**으로 나누어 생각한다. 각 테스트가 어떤 오류를 잡는지 설명할 수 있어야 한다.

```python
import unittest


class TestRemoveBadPairs(unittest.TestCase):
    def test_cases(self):
        cases = [
            ("", ""),             # 빈 입력: stack[-1] 접근 오류 방지
            ("a", "a"),           # 한 문자: 제거할 쌍 없음
            ("abc", "abc"),       # bad pair 없는 입력 유지
            ("aaa", "aaa"),       # 같은 소문자는 유지
            ("AAA", "AAA"),       # 같은 대문자는 유지
            ("aA", ""),           # 소문자 → 대문자 제거
            ("Aa", ""),           # 대문자 → 소문자 제거
            ("aB", "aB"),         # 다른 글자는 대소문자가 달라도 유지
            ("aAbc", "bc"),       # 맨 앞에서 제거
            ("abxXw", "abw"),     # 중간에서 제거
            ("abcC", "ab"),       # 맨 뒤에서 제거
            ("aAbBcC", ""),       # 독립적인 여러 쌍 제거
            ("abBA", ""),         # 연쇄 제거 후 빈 결과
            ("abBAc", "c"),       # 연쇄 제거 후 일부 문자 유지
            ("aaAA", ""),         # 반복 문자 사이에서도 연쇄 제거
        ]

        for s, expected in cases:
            with self.subTest(s=s):
                self.assertEqual(remove_bad_pairs(s), expected)


if __name__ == "__main__":
    unittest.main()
```

추가로 확인할 수 있는 속성:

- **완료 후 안정성:** `f(f(s)) == f(s)`. 이미 모두 제거했으므로 다시 실행해도 결과가 같다.
- **결과에 bad pair가 없음:** 결과의 모든 인접한 두 문자를 검사한다.
- **길이의 홀짝 유지:** 두 문자씩 제거하므로 `(len(s) - len(result)) % 2 == 0`이다.
- **큰 입력:** 입력 길이 제한에 맞춰 `"a" * n`과 `"a" * n + "A" * n` 등을 사용해 각각 최대 스택 크기와 긴 연쇄 제거를 확인한다.

영문자 외의 문자나 잘못된 타입도 지원해야 하는 기능이라면, 허용 입력과 오류 처리 규칙을 먼저 정한 뒤 해당 테스트를 추가한다. 주어지지 않은 `None` 처리 규칙 등을 임의로 가정하지 않는다.

## 기억할 것

- 원본에서 처음 인접했던 쌍만 확인하면 연쇄 제거를 놓친다. `"abBA"`가 대표 반례이다.
- 비교 대상은 원본의 이전 문자가 아니라 **현재 스택의 마지막 문자**이다.
- 스택이 비었는지 먼저 확인한 다음 `stack[-1]`에 접근한다.
- 처음 사용한 스택 풀이 자체는 맞다. 인터뷰에서는 테스트를 범주별로 제시하고 각 테스트의 목적까지 설명한다.
- **기억할 한 문장: 지금까지 정리된 결과를 스택에 유지하고, 새 문자가 맨 위와 반대 대소문자의 같은 글자면 둘을 지운다.**
