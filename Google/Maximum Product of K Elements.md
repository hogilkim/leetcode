# Maximum Product of K Elements

- **Topic:** #greedy #sorting #two-pointers #heap
- **Updated:** Oct 15, 2026
- 문제 번호와 입력 크기 제한은 제공되지 않았다. `1 <= k <= len(nums)`를 가정한다.

## 문제

정수 배열 `nums`에서 **정확히 k개의 원소를 선택하여 만들 수 있는 최대 곱**을 반환한다.

- 선택한 원소들이 연속할 필요는 없다.
- 같은 인덱스는 한 번만 선택한다. 중복 값은 각각 별개의 원소다.
- 양수, 음수, 0이 모두 들어올 수 있다.
- Follow-up 1: 정렬한 뒤 추가 공간 없이 풀기.
- Follow-up 2: 정렬하지 않고 힙으로 풀기.

| 입력 | k | 최대 곱 | 선택 예시 |
| --- | --- | --- | --- |
| `[-10, -8, 9, 7]` | 2 | 80 | `[-10, -8]` |
| `[-10, -7, 9, 8]` | 2 | 72 | `[9, 8]` |
| `[-10, -5, -2, -1]` | 3 | -10 | `[-5, -2, -1]` |
| `[-5, -2, 0]` | 3 | 0 | 모든 원소 |
| `[-5, 0, 2]` | 2 | 0 | `[0, 2]` |
| `[-5, 2]` | 2 | -10 | 모든 원소 |

## 핵심: 곱의 부호와 k의 홀짝

**양수 두 개 또는 음수 두 개를 곱하면 양수**다. 따라서 큰 양수 두 개와 절댓값이 큰 음수 두 개가 경쟁한다.

- `k == n`: 모든 원소를 골라야 하므로 전체 곱이 답이다. 음수인 답도 그대로 반환한다.
- `k`가 홀수이고 양수가 있으면: 가장 큰 양수 하나를 먼저 선택하고, 나머지는 쌍으로 선택한다.
- `k`가 홀수이고 양수가 없으면: 0이 있으면 답은 0이다. 모두 음수라면 어떤 선택도 음수이므로 **0에 가장 가까운 k개**를 골라 곱의 절댓값을 최소화한다.
- 나머지 경우: 가장 좋은 양수 쌍과 음수 쌍을 비교하여 더 큰 곱을 선택한다.

## 풀이 1: 정렬 + 양끝 투 포인터

오름차순으로 정렬한다. `k`가 홀수인 경우를 먼저 처리한 뒤, 남은 선택 개수를 짝수로 만든다.

1. 왼쪽 끝의 두 원소를 곱한다. 큰 절댓값의 음수 두 개가 후보가 된다.
2. 오른쪽 끝의 두 원소를 곱한다. 큰 양수 두 개가 후보가 된다.
3. 더 큰 쌍을 선택하고 해당 포인터를 두 칸 이동한다.
4. `k`를 2씩 줄이며 반복한다.

양수가 없고 `k`가 홀수라면 오른쪽의 k개를 바로 곱한다. 슬라이스를 만들지 않고 인덱스로 순회하여 정렬 후 추가 공간을 일정하게 유지한다.

```python
from math import prod


def max_product_sort(nums, k):
    n = len(nums)

    if k == n:
        return prod(nums)

    nums.sort()
    result = 1

    if k % 2 and nums[-1] <= 0:
        for i in range(n - k, n):
            result *= nums[i]
        return result

    left, right = 0, n - 1

    if k % 2:
        result = nums[right]
        right -= 1
        k -= 1

    while k:
        left_pair = nums[left] * nums[left + 1]
        right_pair = nums[right] * nums[right - 1]

        if left_pair > right_pair:
            result *= left_pair
            left += 2
        else:
            result *= right_pair
            right -= 2

        k -= 2

    return result
```

- 시간: `O(n log n + k) = O(n log n)`.
- 추가 공간: **정렬 이후 O(1)**. 포인터와 누적곱만 사용한다.
- Python의 `list.sort()` 자체는 최악 `O(n)`의 임시 공간을 사용할 수 있다. 전체 과정이 O(1) 공간이라고 설명하지 않는다.
- 입력 배열을 직접 정렬한다. 정렬 후 `nums[-k:]` 같은 슬라이스를 만들면 O(k) 공간이 추가된다.

## 풀이 2: 양수 최대 힙 + 음수 최소 힙

정렬 없이 같은 쌍 선택을 수행한다.

- `positives`: 양수를 부호 반전하여 저장한다. 가장 큰 양수를 먼저 꺼내는 최대 힙이다.
- `negatives`: 음수를 실제 값 그대로 저장한다. 가장 작은 음수, 즉 절댓값이 가장 큰 음수를 먼저 꺼내는 최소 힙이다.
- 두 힙에서 각각 가장 좋은 쌍의 곱을 확인하고, 더 큰 쌍의 원소 두 개만 pop한다.
- 양수 힙의 값은 부호가 반전되어 있지만 **두 개를 곱하면 원래 양수 쌍의 곱과 같다**.

```python
import heapq
from math import prod


def max_product_two_heaps(nums, k):
    if k == len(nums):
        return prod(nums)

    positives = [-x for x in nums if x > 0]
    negatives = [x for x in nums if x < 0]
    heapq.heapify(positives)
    heapq.heapify(negatives)

    result = 1

    if k % 2:
        if not positives:
            if 0 in nums:
                return 0

            # 모두 음수: 기존 힙을 절댓값 최소 힙으로 바꾼다.
            for i in range(len(negatives)):
                negatives[i] = -negatives[i]
            heapq.heapify(negatives)

            return prod(-heapq.heappop(negatives) for _ in range(k))

        result = -heapq.heappop(positives)
        k -= 1

    def pair_product(heap):
        if len(heap) < 2:
            return -1  # 가능한 같은 부호 쌍의 곱은 항상 양수다.

        # 두 번째 최솟값은 루트의 두 자식 중 하나다.
        return heap[0] * min(heap[1:3])

    while k:
        positive_pair = pair_product(positives)
        negative_pair = pair_product(negatives)

        if positive_pair == negative_pair == -1:
            # 원래 k < n이고, 더 고를 같은 부호 쌍이 없다.
            # 남은 원소에는 반드시 0이 있어 최대 곱은 0이다.
            return 0

        heap = positives if positive_pair >= negative_pair else negatives
        result *= heapq.heappop(heap) * heapq.heappop(heap)
        k -= 2

    return result
```

### 힙에서 두 번째 원소 확인하기

힙은 전체가 정렬된 배열이 아니다. `heap[1]`이 반드시 두 번째 최솟값인 것은 아니다.

최솟값은 루트 `heap[0]`이고, 두 번째 최솟값은 루트의 자식인 `heap[1]`, `heap[2]` 중 작은 값이다. 따라서 `min(heap[1:3])`으로 찾는다. 이 슬라이스의 길이는 최대 2이므로 O(1) 시간과 공간이다.

### 쌍이 없을 때 왜 0인가?

코드의 첫 줄에서 원래 `k == n`인 경우를 처리했다. 따라서 이후에는 항상 고를 개수보다 남은 원소 수가 많다.

남은 k는 2 이상의 짝수다. 양수 쌍도 음수 쌍도 없으면 양수와 음수는 각각 최대 하나씩만 남아 있다. 남은 원소 수가 k보다 많으므로 0이 반드시 있다. 남은 원소에서 k개를 고르면 0을 포함해야 하므로 전체 곱은 0이다.

### 복잡도

- 시간: **O(n + k log n)**. 리스트 생성과 `heapify()`는 O(n), 선택한 원소마다 pop은 O(log n)이다. 모두 음수인 예외 처리에서도 같은 상한이다.
- 공간: **O(n)**. 두 힙에 원소를 나눠 저장한다.
- 정렬하지 않으며 입력 배열을 변경하지 않는다.

## 왜 쌍을 Greedy하게 골라도 되는가?

양수 곱을 만들려면 음수는 짝수 개가 필요하다. 홀수 k에서 가장 큰 양수를 먼저 선택한 뒤에는 남은 원소를 같은 부호의 쌍으로 묶을 수 있다.

각 부호 안에서는 절댓값이 큰 원소부터 선택해야 곱이 커진다. 양수는 큰 값 두 개씩, 음수는 가장 작은 값 두 개씩 묶으면 각 부호의 쌍 곱이 큰 순서로 나온다. 매번 두 후보 중 큰 쌍을 고르는 것은 두 내림차순 후보 목록을 합치며 필요한 개수만큼 선택하는 것과 같다.

양수 곱이 불가능한 경우는 따로 처리한다. 모든 원소를 선택해야 하면 전체 곱을 반환하고, 양수가 없는 홀수 k에서는 0 또는 절댓값이 가장 작은 음수들을 선택한다. 쌍을 충분히 만들 수 없고 0이 남은 경우에는 0을 반환한다.

## 틀린 지점 / 헷갈린 지점

### 1. 모두 음수인데 무조건 절댓값이 큰 수부터 고르기

```text
nums = [-10, -5, -2, -1], k = 3

절댓값이 큰 세 개: (-10) × (-5) × (-2) = -100
0에 가까운 세 개:  (-5) × (-2) × (-1) = -10  ← 최대
```

음수인 답에서는 절댓값이 작을수록 실제 값이 크다. 모두 음수여도 k가 짝수이면 절댓값이 큰 수부터 고른다.

### 2. 힙 하나에서 음수 하나를 temp에 보관하면 비교가 필요 없다고 생각하기

하나의 힙에 `(-abs(x), sign)`을 저장하면 절댓값이 큰 순서로 pop할 수 있다. 첫 음수는 `temp`에 두고, 양수는 곧바로 선택하고, 다음 음수가 나오면 두 음수를 함께 선택하려는 아이디어다.

**문제는 남은 선택 자리가 하나일 때다.**

```text
nums = [-10, 9, -8, 7], k = 2
pop 순서: -10 → 9 → -8 → 7

-10: temp에 보관
  9: 선택 → 한 자리만 남음
 -8: temp와 묶으면 80이지만 두 자리가 필요함

정답은 [-10, -8]이므로 이미 선택한 9를 취소해야 한다.
```

그렇다고 양수를 무조건 취소해도 안 된다.

```text
nums = [100, 99, -80, -60, 59], k = 3
100과 99를 선택한 뒤 음수 쌍을 만남

99를 취소하고 음수 쌍 선택: 100 × 80 × 60 = 480,000
99를 유지하고 59 선택:     100 × 99 × 59 = 584,100  ← 최대
```

- 절댓값 순서의 첫 음수 두 개는 **음수 쌍 중에서는** 최선이다. 양수 후보와의 비교는 여전히 필요하다.
- 하나의 힙으로도 풀 수 있지만, 선택 취소와 교체를 판단하는 추가 로직이 필요하다.
- **두 힙이 필수인 것은 아니다. 두 힙을 쓰면 선택 전에 양수 쌍과 음수 쌍을 비교하기 쉽다.**

## 기억할 것

- **홀수 k를 먼저 처리하고, 나머지는 양수 쌍 vs 음수 쌍으로 비교한다.**
- 양수가 없는 홀수 k: 0이 있으면 0, 모두 음수이면 0에 가까운 k개.
- `k == n`이면 선택의 여지가 없다. 전체 곱이 음수여도 그대로 반환한다.
- 힙의 원소 순서와 두 원소를 곱한 값의 순서는 다르다.
- 정렬 풀이의 O(1) 공간은 **정렬 이후**를 뜻한다. 두 힙 풀이는 O(n) 공간이다.
