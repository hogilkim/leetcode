# Tasks in Cyclic Dependencies

- **Topic:** #graph #dfs #backtracking #cycle-detection #scc
- **Updated:** Oct 15, 2026
- 인터뷰 문제를 정리한 것으로, 별도 문제 번호와 입력 크기 제한은 제공되지 않았다.

## 문제

작업 목록 `tasks`와 작업 사이의 의존 관계 `dependencies`가 주어진다. **사이클에 직접 포함되는 모든 작업의 집합**을 반환한다. 사이클이 없으면 빈 집합을 반환한다.

- 작업은 방향 그래프의 노드다.
- 이 노트에서 `(a, b)`는 `a`를 먼저 완료해야 `b`를 수행할 수 있다는 뜻이며, 간선 `a → b`로 표현한다.
- 서로 연결되지 않은 작업 그룹이 있을 수 있다.
- 자기 자신으로 향하는 간선도 사이클이다.
- 사이클 때문에 실행할 수 없는 작업이라도, **그 작업 자체가 사이클에 포함되지 않으면 반환하지 않는다.**

### 예시 1: 사이클 이후의 작업은 제외

```text
tasks = ["A", "B", "C", "D", "E"]
dependencies = [
    ("A", "B"),
    ("B", "C"),
    ("C", "A"),
    ("C", "D"),
    ("D", "E"),
]

A → B → C → A
        ↓
        D → E

결과: {"A", "B", "C"}
```

`D`, `E`에서 자기 자신으로 돌아오는 경로는 없으므로 결과에서 제외한다.

### 예시 2: 여러 사이클의 작업을 모두 수집

```text
tasks = ["A", "B", "C"]
dependencies = [("A", "B"), ("B", "A"), ("A", "C"), ("C", "B")]

사이클 1: A → B → A
사이클 2: A → C → B → A

결과: {"A", "B", "C"}
```

## 풀이: DFS + 현재 경로 백트래킹

이 풀이는 **이전에 탐색을 마친 작업도 다른 경로에서 다시 탐색**한다. 전역 `visited`로 건너뛰지 않는다.

- `path`: 현재 DFS 경로의 작업 목록.
- `position`: 현재 경로에 있는 각 작업의 인덱스. 현재 경로의 방문 집합 역할도 한다.
- `cycle_tasks`: 발견한 모든 사이클 작업의 합집합.

1. 현재 작업이 이미 `position`에 있다면 현재 경로에서 같은 작업으로 돌아왔으므로 사이클이다.
2. 그 작업이 처음 나온 위치부터 경로 끝까지를 결과 집합에 추가하고, 이번 호출을 종료한다.
3. 현재 경로에 없는 작업이면 `position`에 위치를 기록하고 `path.append(task)`한다.
4. 모든 이웃을 재귀 탐색한다.
5. 탐색 후 `path.pop()`과 `del position[task]`로 경로 상태를 복원한다.
6. 연결되지 않은 그룹도 확인하도록 모든 작업을 시작점으로 DFS한다.

## 코드

```python
def find_cycle_tasks(tasks, dependencies):
    # (a, b) means a must finish before b.
    graph = {task: [] for task in tasks}

    for a, b in dependencies:
        graph.setdefault(a, []).append(b)
        graph.setdefault(b, [])

    path = []
    position = {}
    cycle_tasks = set()

    def dfs(task):
        if task in position:
            start = position[task]
            cycle_tasks.update(path[start:])
            return

        position[task] = len(path)
        path.append(task)

        for neighbor in graph[task]:
            dfs(neighbor)

        path.pop()
        del position[task]

    for task in graph:
        dfs(task)

    return cycle_tasks
```

## `path[start:]`만 수집하는 이유

현재 상태가 다음과 같다고 하자.

```python
path = ["X", "A", "B", "C"]
position = {"X": 0, "A": 1, "B": 2, "C": 3}
```

`C → A` 간선을 따라 `dfs("A")`를 호출하면, `A`는 현재 경로에 이미 존재한다.

```text
X → A → B → C
    ↑       |
    └───────┘
```

```python
start = position["A"]        # 1
cycle_tasks.update(path[1:])  # A, B, C를 결과에 추가
```

`A`부터 `C`까지 간 뒤 `A`로 돌아오므로 사이클은 `{A, B, C}`다. `X`로 돌아오는 간선은 없으므로 전체 `path`를 추가하면 안 된다.

여기서 `return`은 **중복된 작업을 발견한 이번 호출만 종료**한다. 이 호출은 작업을 새로 append하지 않았으므로 pop도 하지 않는다. 부모 호출은 남은 이웃을 계속 탐색하고, 자신이 추가했던 작업을 마지막에 pop한다.

## 전역 `visited`로 건너뛰면 생기는 문제

```text
A → B → A
A → C → B
```

1. `A`에서 `B`를 먼저 탐색하면 `A → B → A`를 발견하고 `{A, B}`를 수집한다.
2. `B` 탐색이 끝난 뒤 `A → C → B`를 탐색한다.
3. 전역 `visited` 때문에 `B`를 건너뛰면 `A → C → B → A`를 놓쳐 `C`를 결과에 넣지 못할 수 있다.

따라서 **현재 경로에서 반복되는 작업은 사이클로 처리하되, 다른 경로에서 탐색을 마친 작업은 다시 탐색**한다. `position`은 재귀가 끝날 때 삭제하므로 경로별로 관리된다.

또한 단순히 전역 방문 기록이 있다는 것만으로 사이클이라고 판단하면 안 된다. 예를 들어 `A → B → D`, `A → C → D`에서 `D`를 두 번 만나지만 사이클은 없다.

## 왜 모든 사이클 작업을 찾는가?

현재 경로에 같은 작업이 나타났다면, 그 작업부터 경로 끝까지의 간선과 마지막 복귀 간선이 실제 사이클을 이룬다. 따라서 결과에는 사이클에 속하는 작업만 추가된다.

반대로 어떤 사이클의 한 작업을 시작점으로 잡으면, DFS는 그 사이클을 따라가는 경로도 탐색한다. 시작 작업으로 돌아올 때 사이클의 모든 작업을 수집한다. 모든 작업을 시작점으로 탐색하므로 어떤 사이클도 놓치지 않는다.

현재 경로에 있는 작업을 다시 만나면 즉시 반환하므로 무한 재귀는 발생하지 않는다.

## 복잡도

`V`는 작업 수, `E`는 간선 수다. 해시 조회·추가·삭제는 평균 `O(1)`이며, 같은 방향의 중복 간선이 없는 그래프를 기준으로 한다.

- **시간: 최악의 경우 `O(V² · V!)`.** 전역 방문 처리 없이 모든 시작점에서 서로 다른 단순 경로를 탐색하므로 경로 수가 팩토리얼 규모까지 늘어난다. 한 경로 상태에서 최대 `V`개 이웃을 확인하고, 사이클을 만날 때 `path[start:]` 복사와 집합 갱신에 최대 `O(V)`가 든다. 그래프 구성에는 별도로 `O(V + E)`가 든다.
- **공간: 그래프 포함 `O(V + E)`.** 현재 경로, 위치 딕셔너리, 결과 집합, 재귀 스택 및 임시 슬라이스는 각각 `O(V)`다. 모든 경로를 한꺼번에 저장하지는 않는다.

일반 DFS의 `O(V + E)`를 그대로 적용할 수 없다. **이 코드는 같은 작업과 간선을 여러 경로에서 반복 탐색한다.** 큰 그래프에서는 실행 시간과 Python의 재귀 깊이 제한이 문제가 될 수 있다.

## 최적화: 강한 연결 요소(SCC)

모든 사이클 작업을 효율적으로 찾으려면 Tarjan 또는 Kosaraju 알고리즘으로 SCC를 구한다. SCC는 내부의 모든 작업이 서로에게 도달할 수 있는 최대 그룹이다.

- 작업이 두 개 이상인 SCC의 작업은 모두 사이클에 속한다.
- 작업이 하나인 SCC는 자기 자신으로 향하는 간선이 있을 때만 포함한다.
- 시간은 `O(V + E)`다.

일반 DFS의 `방문 전 / 현재 탐색 중 / 탐색 완료` 상태는 사이클 **존재 여부**를 선형 시간에 판단할 수 있다. 다만 현재 경로의 사이클 부분만 수집하면서 탐색 완료 작업을 건너뛰는 방식을 그대로 사용하면, 위 예시처럼 일부 사이클 작업을 놓칠 수 있다.

Kahn 위상 정렬 후 남은 작업을 전부 반환하는 것도 주의한다. 사이클에 포함되지 않은 후속 작업까지 남을 수 있다.

## 기억할 것

- `append` → 재귀 → `pop`, 위치 기록 → 재귀 → 위치 삭제로 현재 경로를 복원한다.
- 사이클 판정 기준은 **현재 경로에 존재하는가**다.
- 사이클을 만나면 `path` 전체가 아니라 `path[position[task]:]`만 수집한다.
- 결과는 집합으로 모아 여러 사이클에 등장한 작업을 중복 제거한다.
- 사이클 하나를 찾았다고 전체 탐색을 종료하지 않는다.
- 빈 입력, 사이클 없는 그래프, 자기 자신으로 향하는 간선, 분리된 여러 사이클도 처리한다.
- 이 백트래킹 풀이는 정답을 찾지만 최악의 시간은 팩토리얼이다. 선형 시간에 모든 사이클 작업을 찾는 방법은 SCC다.
