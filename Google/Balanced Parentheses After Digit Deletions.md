# Balanced Parentheses After Digit Deletions

- **Topic:** #dynamic-programming #parentheses #state-space
- **Updated:** Oct 14, 2026
- 문제 번호와 입력 길이 제한은 제공되지 않았다.

## 문제

문자열 `s`는 `'('`, `')'`, `'0'`–`'9'`로 구성된다. 숫자를 왼쪽부터 하나씩 처리한다. 값이 `k`인 숫자를 만나면 **현재 그 숫자의 왼쪽에 남아 있는 괄호 중 정확히 `k`개를 골라 삭제**하고, 숫자도 제거한다. 왼쪽에 괄호가 `k`개보다 적으면 해당 삭제 방법은 불가능하다.

모든 숫자를 처리한 후 올바른 괄호 문자열을 만드는 삭제 방법이 하나라도 있으면 `True`, 없으면 `False`를 반환한다. 빈 문자열도 올바르다. 숫자 `"12"`는 12개 삭제가 아니라, 1개 삭제 후 2개 삭제하는 두 연산이다.

| 입력 | 결과 | 설명 |
| --- | --- | --- |
| `"(()1"` | `True` | 여는 괄호 하나를 삭제하면 `"()"` |
| `")(1)"` | `True` | 첫 번째 닫는 괄호를 삭제하면 `"()"` |
| `"(2"` | `False` | 숫자 왼쪽에 괄호가 하나뿐이다 |
| `"((11"` | `True` | 각 숫자가 여는 괄호 하나씩 삭제하여 빈 문자열이 된다 |
| `"()0"` | `True` | 삭제 없이 `"()"`가 남는다 |

## 핵심 아이디어: 삭제할 괄호를 미리 선택한다

왼쪽에서 오른쪽으로 읽으며 각 괄호를 **삭제 대상으로 선택하거나 최종 문자열에 유지한다.** 삭제 대상으로 선택하는 것은 실제로 즉시 삭제한다는 뜻이 아니다. 뒤에 나오는 숫자가 그 선택을 사용해서 삭제한다.

숫자마다 어떤 괄호를 지웠는지 모두 저장할 필요는 없다. 지금까지 선택한 미사용 삭제 대상은 모두 현재 숫자의 왼쪽에 있으므로, **그 개수만 알면 삭제 가능 여부를 확인할 수 있다.** 유지한 괄호도 문자열 전체 대신 unmatched opening의 개수로 표현한다.

## DP 상태

`states`는 지금까지 가능한 `(deletions, balance)`를 저장하는 집합이다.

- `deletions`: 지금까지 삭제 대상으로 선택했지만 아직 숫자가 사용하지 않은 괄호 수.
- `balance`: 유지한 괄호 중 아직 닫히지 않은 `'('`의 수.

초기 상태는 `{(0, 0)}`이다. 같은 상태에 도달한 경로는 이후 가능한 선택이 같으므로 `set`으로 합친다.

### 괄호를 만났을 때

1. 삭제 대상으로 선택: `(deletions + 1, balance)`.
2. 유지:
   - `'('`이면 `(deletions, balance + 1)`.
   - `')'`이면 `balance > 0`일 때만 `(deletions, balance - 1)`.

유지할 `')'` 앞에 유지한 `'('`이 없다면 그 경로는 불가능하다. 이후의 여는 괄호로 앞의 닫는 괄호를 매칭할 수는 없다. 대신 그 `')'`를 삭제 대상으로 선택하는 분기는 가능하다.

### 숫자 `k`를 만났을 때

`deletions >= k`인 상태만 남기고 `(deletions - k, balance)`로 이동한다. 선택한 괄호 중 `k`개를 이 숫자가 삭제하는 것이다. 나머지는 이후 숫자를 위해 남겨둘 수 있다.

### 종료 조건

`(0, 0)`이 `states`에 있으면 성공이다.

- `deletions == 0`: 선택한 모든 삭제 대상이 실제 숫자 연산에 사용되었다.
- `balance == 0`: 유지한 모든 여는 괄호가 닫혔다. 닫는 괄호를 유지할 때도 검사했으므로 최종 문자열이 올바르다.

## 코드: 사전 집계 없이 왼쪽 → 오른쪽

```python
def can_make_valid(s: str) -> bool:
    states = {(0, 0)}

    for ch in s:
        next_states = set()

        for deletions, balance in states:
            if ch.isdigit():
                k = int(ch)

                # 현재 숫자 왼쪽의 미사용 삭제 대상이 충분한지 확인한다.
                if deletions >= k:
                    next_states.add((deletions - k, balance))

            else:
                # 이 괄호를 이후 숫자가 삭제하도록 선택한다.
                next_states.add((deletions + 1, balance))

                # 이 괄호를 최종 문자열에 유지한다.
                if ch == "(":
                    next_states.add((deletions, balance + 1))
                elif balance > 0:
                    next_states.add((deletions, balance - 1))

        states = next_states

        if not states:
            return False

    return (0, 0) in states
```

전체 삭제 수, 전체 괄호 수, 최종 길이를 미리 계산하지 않는다. 누적 삭제 요구량을 나타내는 `required`도 필요 없다. 숫자가 등장할 때마다 `deletions`에서 직접 차감한다.

## 예시 추적: `")(1)"`

여러 DP 경로 중 성공하는 경로 하나를 따라가면 다음과 같다.

| 문자 | 선택 | 상태 `(deletions, balance)` |
| --- | --- | --- |
| 시작 | — | `(0, 0)` |
| `')'` | 삭제 대상으로 선택 | `(1, 0)` |
| `'('` | 유지 | `(1, 1)` |
| `'1'` | 선택한 괄호 하나를 삭제 | `(0, 1)` |
| `')'` | 유지하고 여는 괄호와 매칭 | `(0, 0)` |

첫 번째 `')'`는 나중의 `'1'`이 삭제한다. 최종적으로 `"()"`가 남는다.

## 왜 올바른가?

**DP의 성공 경로는 실제 연산으로 실행할 수 있다.** 각 숫자는 자신보다 앞에서 선택한 미사용 괄호만 소비한다. 그 괄호들은 숫자의 왼쪽에 있고, 이전 숫자가 사용한 괄호는 개수에서 이미 빠져 있으므로 다시 삭제하지 않는다. 어느 미사용 대상을 먼저 소비하든 나머지는 이후 숫자의 왼쪽에도 있으므로 가능성은 동일하다. 종료 시 미사용 대상이 없고 유지한 괄호가 균형을 이루면 모든 규칙을 만족한다.

**실제 성공하는 삭제 방법도 DP에 포함된다.** 실제로 삭제되는 괄호는 삭제 분기를, 남는 괄호는 유지 분기를 선택한다. 각 숫자의 삭제 대상은 그 숫자 전에 선택되므로 `deletions >= k`를 만족한다. 최종 문자열이 올바르면 유지한 괄호의 모든 접두사도 balance가 음수가 되지 않는다. 따라서 해당 경로는 버려지지 않고 `(0, 0)`에 도달한다.

## 복잡도

문자열 길이가 `n`일 때 `deletions`와 `balance`는 각각 최대 `n`이다.

- 가능한 상태 수: 최대 `O(n²)`.
- 시간: 각 문자마다 상태를 순회하므로 최악 `O(n³)`.
- 공간: 현재/다음 상태 집합을 저장하므로 최악 `O(n²)`.

입력 길이 제한이 없으므로 이 풀이가 큰 입력에서도 충분히 빠르다고 보장할 수는 없다.

## 헷갈린 지점 / 기억할 것

- `deletions`는 이미 실제로 삭제한 총개수가 아니라 **앞에서 선택한 미사용 삭제 대상 수**다. 숫자를 만나면 감소한다.
- 괄호를 삭제 대상으로 선택했다고 실제 규칙의 삭제 시점을 바꾼 것은 아니다. DP가 뒤의 숫자에 사용할 대상을 미리 계획하는 것이다.
- 숫자에서 `deletions == k`를 요구하면 안 된다. `"((11"`처럼 대상을 여러 개 선택해 두고 여러 숫자가 나누어 사용할 수 있다.
- 끝에서 `balance == 0`만 확인하면 안 된다. 예를 들어 `"("`을 삭제 대상으로 선택한 상태는 `(1, 0)`이지만 실제로 삭제할 숫자가 없어 실패다.
- 삭제 대상으로 선택한 괄호는 최종 문자열에 포함되지 않으므로 `balance`를 바꾸지 않는다.
- `next_states`를 따로 만들어 현재 문자에서 만든 상태를 같은 문자에 다시 적용하지 않는다.
- **기억할 한 문장: 괄호에서는 삭제/유지를 분기하고, 숫자에서는 앞의 미사용 삭제 대상을 소비한다. 끝은 `(0, 0)`.**
