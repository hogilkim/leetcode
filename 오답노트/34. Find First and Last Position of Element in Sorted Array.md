# LeetCode 34 — Find First and Last Position of Element in Sorted Array · 오답노트

작성일: 2026-10-02  
복습 주제: Binary Search, `bisect_left`, **`bisect_right`**, 경계 설정

## 문제

오름차순 배열에서 `target`의 첫 번째와 마지막 인덱스를 반환한다. 없으면 `[-1, -1]`을 반환하며, 시간 `O(log n)`에 찾아야 한다.

## 꼭 기억할 것

**삽입 위치를 찾는 아래 템플릿에서는 `l = 0`, `r = len(nums)`로 시작한다.**

- `bisect_left`: `target` **이상인 첫 위치**. 같은 값들 앞에 삽입한다.
- `bisect_right`: `target` **보다 큰 첫 위치**. 같은 값들 뒤에 삽입한다.
- 그런 값이 없으면 둘 다 `len(nums)`를 반환할 수 있다.
- 따라서 34번의 마지막 일치 인덱스는 **`bisect_right(nums, target) - 1`**이다.

```text
nums = [1, 2, 2, 2, 4], target = 2
index   0  1  2  3  4

bisect_left  = 1
bisect_right = 4
정답         = [1, 3]
```

## 내가 틀린 이유

### 1. bisect_right의 반환값을 마지막 일치 인덱스와 혼동했다

`bisect_right`는 마지막 `target`의 인덱스가 아니라 **그 다음 삽입 위치**를 반환한다. `right - 1`을 정답으로 쓰려면 검색이 배열 끝 다음 위치까지 도달할 수 있어야 한다.

### 2. r = len(nums) - 1로 시작해 배열 끝 다음 위치를 제외했다

내 오른쪽 검색은 `nums[mid] <= target`이면 `l = mid + 1`로 이동하는 삽입 위치 검색이었는데, `r`을 마지막 원소의 인덱스로 설정했다.

```python
# 잘못 사용한 초기 경계
l, r = 0, len(nums) - 1
```

실패 예시: `nums = [1]`, `target = 1`.

```text
l = 0, r = 0
while l < r → 처음부터 False
right = 0
[left, right - 1] → [0, -1]  # 오답
```

올바른 초기 경계는 `r = len(nums)`이다.

```text
l = 0, r = 1
mid = 0
nums[0] <= 1 → l = 1
l == r → 종료
bisect_right = 1
[left, right - 1] → [0, 0]  # 정답
```

### 3. 반복 조건과 경계 이동 규칙을 섞었다

처음에는 `while l <= r`와 `r = mid` / `l = mid`를 함께 써서 경계가 변하지 않는 경우가 있었다. 이후 `while l < r`에서도 내림한 `mid`에 대해 `l = mid`를 사용하면 원소 두 개가 남았을 때 멈추지 않을 수 있었다.

아래 템플릿은 `while l < r`, `l = mid + 1`, `r = mid`를 함께 사용한다. 매 반복마다 구간이 줄어든다.

## 왜 r = len(nums)인가?

배열에서 검사하는 구간은 **`[l, r)`**이다. `l`은 포함하고 `r`은 제외한다. 처음에 `[0, len(nums))`는 배열 전체를 나타낸다.

길이가 `n`인 배열에는 삽입 위치가 `0`부터 `n`까지 있다. 마지막 원소 뒤에 삽입하는 위치 `n`도 반환할 수 있어야 한다.

`r = n`이어도 `nums[n]`을 읽지 않는다. 반복문 안에서는 `l < r`이므로 `mid < r <= n`이고, 따라서 `mid < n`이다.

**이 규칙은 여기서 사용하는 삽입 위치 검색 템플릿에 해당한다.** 마지막 일치 인덱스를 직접 찾는 닫힌 구간 검색은 `r = len(nums) - 1`을 사용할 수 있지만, 그 경우 경계 이동 규칙과 반환값도 맞춰야 한다.

## 복습용 정답 코드

두 검색의 차이는 `< target`과 `<= target`뿐이다. 오른쪽 검색은 같은 값도 건너뛰어야 한다.

```python
class Solution:
    def searchRange(self, nums: list[int], target: int) -> list[int]:
        # bisect_left: target 이상인 첫 위치
        l, r = 0, len(nums)
        while l < r:
            mid = (l + r) // 2
            if nums[mid] < target:
                l = mid + 1
            else:
                r = mid

        left = l
        if left == len(nums) or nums[left] != target:
            return [-1, -1]

        # bisect_right: target보다 큰 첫 위치
        l, r = 0, len(nums)
        while l < r:
            mid = (l + r) // 2
            if nums[mid] <= target:
                l = mid + 1
            else:
                r = mid

        return [left, l - 1]
```

시간 복잡도: `O(log n)` · 추가 공간: `O(1)`.

## left == len(nums)를 먼저 검사하는 이유

`nums = [2]`, `target = 3`이면 `bisect_left`는 `1`을 반환한다. `nums[1]`은 없으므로 배열 접근 전에 검사해야 한다. 빈 배열도 같은 검사로 처리된다.

```python
if left == len(nums) or nums[left] != target:
    return [-1, -1]
```

Python의 `or`는 왼쪽이 참이면 오른쪽을 평가하지 않는다. 반면 `nums = [2]`, `target = 2`이면 `left = 0`이므로 정상적으로 `nums[0]`을 확인한다.

## 다시 풀 때 확인할 예시

| nums | target | bisect_left | bisect_right | 정답 |
| --- | --- | --- | --- | --- |
| `[]` | `2` | `0` | `0` | `[-1, -1]` |
| `[1]` | `1` | `0` | `1` | `[0, 0]` |
| `[2]` | `1` | `0` | `0` | `[-1, -1]` |
| `[2]` | `3` | `1` | `1` | `[-1, -1]` |
| `[2, 2]` | `2` | `0` | `2` | `[0, 1]` |
| `[1, 2, 2]` | `2` | `1` | `3` | `[1, 2]` |
| `[1, 2, 2, 2, 4]` | `2` | `1` | `4` | `[1, 3]` |
| `[1, 3]` | `2` | `1` | `1` | `[-1, -1]` |

존재하지 않는 target의 삽입 위치도 유효한 숫자이므로, 위치를 찾은 뒤 반드시 실제 값이 target인지 확인한다. 위 정답 코드는 존재 여부 검사에서 반환하면 오른쪽 검색을 생략한다.
