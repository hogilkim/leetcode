## 기억할 것

- Because you already checked that `nums[idx] != target`, you can safely exclude `idx` from the remaining search range.

## 왜

- The loop body tests `nums[idx] == target` first and returns on a hit. So by the time you reach the branch that shrinks the range, `idx` is *proven* not to be the answer.
- That means both sides can skip it: `r = idx - 1` and `l = idx + 1`. Keeping `idx` in the range (`r = idx`) is not wrong, but it re-examines a cell you already ruled out — and with `while l <= r` it never shrinks the range, so it loops forever when `l == r == idx`.

```python
while l <= r:
    idx = (l + r) // 2
    if nums[idx] == target:   # idx is settled here
        return idx
    if target < nums[idx]:
        r = idx - 1           # exclude idx
    else:
        l = idx + 1           # exclude idx
return -1
```

## 틀린 지점 / 헷갈린 지점

- `r = idx` vs `r = idx - 1` — only pick `r = idx` when the loop does **not** check equality inside (the `while l < r` boundary-search form, which ends with `l == r` and needs a final `nums[r] == target` check). If you check equality inside, always use `idx ± 1`.
