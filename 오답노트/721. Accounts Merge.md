## 문제

각 계정은 `[이름, 이메일1, 이메일2, ...]`로 주어진다. 같은 이메일을 공유하는 계정들을 하나로 합치고, 각 사람의 이메일을 중복 없이 정렬해 반환한다. **이름이 같다는 이유만으로 합치지는 않는다.**

## 풀이

최신 풀이는 **이메일을 노드로 하는 무방향 그래프 + DFS**다.

1. `hashmap[email] = name`으로 이메일의 소유자 이름을 저장한다.
2. 각 계정의 첫 이메일 `account[1]`을 중심으로, 계정의 모든 이메일과 **양방향**으로 연결한다. 모든 이메일 쌍을 연결할 필요는 없다.
3. 아직 방문하지 않은 이메일에서 DFS를 시작한다. 방문 즉시 `visited`에 넣고 `tmplist`에 이메일을 모은다.
4. DFS가 끝나면 `[hashmap[email]] + sorted(tmplist)`를 결과에 추가한다.

같은 계정의 이메일은 서로 연결되고, 계정 사이에 공통 이메일이 있으면 두 그룹도 연결된다. 따라서 **연결 요소 하나가 합쳐야 할 계정 하나**이며, DFS로 간접 연결까지 모두 찾을 수 있다.

예: `["John", "a", "b"]`, `["John", "b", "c"]` → `a ↔ b ↔ c` → `["John", "a", "b", "c"]`.

전체 이메일 등장 횟수를 `M`, 고유 이메일 수를 `V`라 하면 그래프 구성과 DFS는 `O(M + V)`, 정렬까지 포함한 시간은 최악 `O(M + V log V)`, 추가 공간은 `O(M + V)`다.

## 기억할 것

- 병합 기준은 **공통 이메일**이다. 이름은 결과에 붙이는 정보다.
- 첫 이메일과 나머지만 연결해도 계정 전체를 탐색할 수 있다. 이메일 하나뿐인 계정도 최신 코드의 자기 자신 연결로 그래프에 포함된다.
- `visited`는 모든 DFS에서 공유한다. 순환을 막고 각 이메일을 한 번만 결과에 넣는다.
- DFS 탐색 순서와 출력 순서는 다르므로, 모은 이메일은 마지막에 정렬한다.

## 틀린 지점 / 헷갈린 지점

- 최신 코드에는 `from collections import defaultdict`가 있으므로 그래프 생성은 `defaultdict(set)`으로 써야 한다. 현재의 `collections.defaultdict(set)`을 쓰려면 `import collections`가 필요하다.
