# 35. Search Insert Position

## 기억할 것

- `while l < r` + `r = len(nums)` → the loop ends at `l == r`, and `l` is the insert position. Never returns -1.
- `while l <= r` → exact-match search, both sides skip `mid` (`mid ± 1`), returns -1 when missing.

## 왜

```python
l, r = 0, len(nums)          # range [l, r) includes the slot *after* the last element
while l < r:                 # stop when one position is left
    mid = (l + r) // 2
    if nums[mid] < target:
        l = mid + 1          # mid is too small, insert goes right of it
    else:
        r = mid              # nums[mid] >= target: mid may BE the answer, keep it
return l                     # first index with nums[i] >= target == bisect_left
```

- Invariant: everything left of `l` is `< target`, everything at `r` or beyond is `>= target`. The range only shrinks and never skips the answer.
- `l = mid + 1` guarantees progress. `l = mid` loops forever when `r == l + 1`.
- Duplicates: `<` gives the leftmost slot (`bisect_left`); `<=` gives the rightmost (`bisect_right`).

## 틀린 지점 / 헷갈린 지점

- `r = len(nums)` not `len(nums) - 1` — the target may go after the last element.
- `r = mid` not `mid - 1` — equality is not checked inside the loop, so `mid` is still a candidate. Compare with [[704. Binary Search]], where equality is checked inside and `mid` is excluded on both sides.
