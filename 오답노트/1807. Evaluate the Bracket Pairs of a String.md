## 문제

문자열 `s`와 `[key, value]` 쌍으로 구성된 `knowledge`가 주어진다. 괄호 안의 key를 대응하는 value로 바꾸고, 모르는 key는 `"?"`로 바꾼 최종 문자열을 반환한다.

원래 문제는 중첩 괄호가 없지만, 이 노트에서는 **중첩을 허용하고 가장 안쪽 괄호부터 평가한다.** 안쪽 괄호의 결과는 바깥쪽 key의 일부가 된다.

```python
s = "(test(name)test)"
knowledge = [["name", "alice"], ["testalicetest", "success"]]
```

```text
(test(name)test) → (testalicetest) → success
```

괄호는 올바르게 짝지어졌다고 가정한다. 치환된 value는 일반 텍스트로 취급하며, value 안의 괄호를 다시 평가하지 않는다.

## 풀이

해시맵으로 key를 조회하고, 스택으로 각 괄호 깊이에서 만들고 있는 문자열을 관리한다.

1. `stack = [""]`로 시작한다. 맨 아래 문자열은 괄호 밖의 최종 결과를 모은다.
2. `(`를 만나면 빈 문자열을 push해서 새 key를 만들기 시작한다.
3. 일반 문자는 `stack[-1]`에 붙인다.
4. `)`를 만나면 완성된 key를 pop하고 해시맵에서 찾는다. 그 value를 부모 버퍼인 `stack[-1]`에 붙인다.
5. 모든 문자를 처리하면 `stack[0]`을 반환한다.

### 내가 작성한 코드 — 정답

```python
class Solution:
    def evaluate(self, s: str, knowledge: list[list[str]]) -> str:
        convert_map = {}
        for key, val in knowledge:
            convert_map[key] = val

        stack = [""]

        for char in s:
            if char == "(":
                stack.append("")
            elif char == ")":
                key = stack.pop()
                value = convert_map.get(key, "?")
                stack[-1] += value
            else:
                stack[-1] += char

        return stack[0]
```

## 왜: 안쪽 괄호가 먼저 해결되는가?

스택의 맨 위는 **현재 가장 안쪽 괄호의 key**다. `)`를 만났을 때 그 key의 내부 괄호는 이미 모두 처리되었으므로, 곧바로 조회할 수 있다. 조회 결과를 부모에 붙이면 바깥쪽 key를 계속 만들 수 있다. 재귀 함수를 쓰지 않아도 스택이 각 깊이의 작업을 기억한다.

`name → alice`, `testalicetest → success`일 때:

| 처리한 부분 | stack | 의미 |
|---|---|---|
| 시작 | `[""]` | 최종 결과 버퍼 |
| `(test` | `["", "test"]` | 바깥쪽 key 작성 중 |
| `(test(name` | `["", "test", "name"]` | 안쪽 key 작성 중 |
| `(test(name)` | `["", "testalice"]` | `name`을 평가해서 부모에 추가 |
| `(test(name)test` | `["", "testalicetest"]` | 바깥쪽 key 완성 |
| `(test(name)test)` | `["success"]` | 바깥쪽 key 평가 완료 |

## 개선: 문자열 대신 조각 리스트로 누적

파이썬 문자열은 immutable이다. `stack[-1] += char`는 기존 문자열을 반복해서 복사할 수 있다. 괄호 없는 길이 `n`의 문자열만으로도 복사량이 `1 + 2 + … + n`이 되어 최악의 경우 `O(n²)` 시간이 걸린다.

각 버퍼를 리스트로 두고 `append()`로 조각을 모은 뒤, key가 완성되거나 최종 결과를 반환할 때 `join()`한다.

```python
class Solution:
    def evaluate(self, s: str, knowledge: list[list[str]]) -> str:
        convert_map = dict(knowledge)
        stack = [[]]

        for char in s:
            if char == "(":
                stack.append([])
            elif char == ")":
                key = "".join(stack.pop())
                value = convert_map.get(key, "?")
                stack[-1].append(value)
            else:
                stack[-1].append(char)

        return "".join(stack[0])
```

### 복잡도

개선한 코드에서 `n`은 입력 문자열 길이, `K`는 knowledge 전체 문자열 길이, `E`는 평가한 모든 key 길이의 합, `L`은 최종 결과 길이라고 하자.

- **시간:** 해시맵의 평균적인 조회 비용을 가정하면 `O(K + n + E + L)`. key를 만들고 해싱할 때 그 길이만큼 읽으며, 마지막 결과도 길이만큼 합친다.
- **공간:** 해시맵, 스택의 조각들, 생성한 key와 결과를 포함한 보수적인 상한은 `O(K + n + E + L)`이다. 스택 프레임 수는 최대 중첩 깊이 + 1이다.

중첩 버전에서는 치환값이 바깥쪽 key를 길게 만들 수 있으므로, 입력 `s`를 한 번 순회한다는 이유만으로 전체 시간을 무조건 `O(n)`이라고 하면 안 된다. 리스트 방식도 각 깊이에서 완성된 key를 만들 때는 문자열을 읽고 복사한다.

## 기억할 것

- `(` → 새 버퍼 push, `)` → key를 pop하고 평가한 value를 부모에 추가.
- `stack[0]`은 최종 결과, `stack[-1]`은 현재 작업 중인 버퍼다.
- 안쪽 key가 없으면 `"?"`가 부모 key에 포함된다. `name`이 없으면 바깥쪽 key는 `"test?test"`이며, 이 key를 다시 조회한다.
- 바깥쪽 key도 없으면 그 괄호 전체가 `"?"`가 된다. 안쪽 결과를 그대로 반환하지 않는다.
- 여러 괄호나 일반 텍스트가 섞여도 동일하게 처리한다. `"Hi (name)!"`은 `"Hi alice!"`가 된다.

## 틀린 지점 / 헷갈린 지점

- 이번 코드는 로직상 틀리지 않았다. 중첩 괄호를 이미 올바르게 처리한다.
- 바깥쪽 조회 대상은 원래의 `"test(name)test"`가 아니라, 안쪽 평가를 마친 `"testalicetest"`다.
- `stack = []`로 시작하면 가장 바깥쪽 `)`를 처리한 뒤 부모 버퍼가 없어지므로, 결과를 모을 초기 버퍼가 필요하다.
- 정답 여부와 문자열 연결 효율은 별개다. 복습할 개선점은 `+=` 누적을 리스트와 `join()`으로 바꾸는 것이다.
