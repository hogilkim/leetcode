## 기억할 것

- **Preorder = root → left → right**, **inorder = left → root → right**. Both are DFS traversal orders.
- `preorder[0]` is the root of the **current subtree**. Find that value in the current `inorder` to divide the left and right subtrees.
- `divide_idx = inorder.index(preorder[0])` is also the **number of nodes in the left subtree**: exactly that many values appear before the root in inorder.
- In preorder, skip the root, take that many nodes for the left subtree, then give the remaining nodes to the right subtree.

```python
root = TreeNode(val=preorder[0])
divide_idx = inorder.index(root.val)
left_size = divide_idx

root.left = self.buildTree(
    preorder[1 : 1 + left_size], inorder[:divide_idx]
)
root.right = self.buildTree(
    preorder[1 + left_size :], inorder[divide_idx + 1 :]
)
```

Python slices include the start and exclude the end. `preorder[1 : 1 + left_size]` therefore contains exactly `left_size` nodes.

## 왜: 내려갈 때 index가 어떻게 바뀌는가

For the current call, with `k = divide_idx`:

```text
preorder: [root] [left subtree: k nodes] [right subtree]
index:      0          1 ... k             k + 1 ...

inorder:  [left subtree: k nodes] [root] [right subtree]
index:          0 ... k - 1         k       k + 1 ...
```

**The root's inorder index can differ from its preorder index.** Inorder tells us the left subtree's size; that size tells us where to split preorder.

### 현재 풀이: slice하면 index는 다시 0부터 시작

```text
preorder = [3, 9, 20, 15, 7]
inorder  = [9, 3, 15, 20, 7]

        3
       / \
      9   20
         /  \
        15   7
```

| Call / subtree | Current preorder | Current inorder | Root = `preorder[0]` | Local `divide_idx` / left size |
|---|---|---|---|---|
| Whole tree | `[3, 9, 20, 15, 7]` | `[9, 3, 15, 20, 7]` | 3 | 1 |
| 3's left | `[9]` | `[9]` | 9 | 0 |
| 3's right | `[20, 15, 7]` | `[15, 20, 7]` | 20 | 1 |
| 20's left | `[15]` | `[15]` | 15 | 0 |
| 20's right | `[7]` | `[7]` | 7 | 0 |

1. At root **3**, `divide_idx = 1`. Left gets `preorder[1:2] = [9]` and `inorder[:1] = [9]`. Right gets `preorder[2:] = [20, 15, 7]` and `inorder[2:] = [15, 20, 7]`.
2. Descend left to **9**. Its new arrays both have length 1, so its root is again at local preorder index **0**, and its local inorder index is **0**. Both child calls get empty arrays and return `None`.
3. Return to **3**, then descend right to **20**. Its new preorder starts with 20, so its root is at local index **0**. Its local inorder index is **1**, even though 20 was at index **3** in the original inorder.
4. At **20**, left gets `preorder[1:2] = [15]` and `inorder[:1] = [15]`; right gets `preorder[2:] = [7]` and `inorder[2:] = [7]`.
5. **15** and **7** each repeat the leaf case: local root index 0, `divide_idx = 0`, empty children. The calls return their nodes, which attach to 20; 20 then attaches to 3.

### Slice하지 않고 원본 index를 유지한다면

Let `pre_start` be the subtree's root index in the original preorder, and let `[in_left, in_right)` be its range in the original inorder. If `root_idx` is the root's original inorder index:

```text
left_size = root_idx - in_left

left child:  pre_start + 1
             inorder range [in_left, root_idx)

right child: pre_start + 1 + left_size
             inorder range [root_idx + 1, in_right)
```

| Root | Original `pre_start` | Original inorder range | Original `root_idx` | `left_size` |
|---|---|---|---|---|
| 3 | 0 | `[0, 5)` | 1 | 1 |
| 9 | 1 | `[0, 1)` | 0 | 0 |
| 20 | 2 | `[2, 5)` | 3 | 1 |
| 15 | 3 | `[2, 3)` | 2 | 0 |
| 7 | 4 | `[4, 5)` | 4 | 0 |

For **20**, `left_size = 3 - 2 = 1`, so its left child starts at preorder index `2 + 1 = 3` (15), and its right child starts at `2 + 1 + 1 = 4` (7). An empty inorder range (`in_left == in_right`) returns `None`.

## 틀린 지점 / 헷갈린 지점

- Don't use an original inorder index directly as a subtree size: subtract the subtree's `in_left`. In the current slicing solution, `in_left` is always locally 0, so `left_size = divide_idx` works.
- The right subtree does **not** always start at `preorder[2:]`: it starts after the root **and all left subtree nodes**, at `preorder[1 + left_size:]`.
- Each recursive call receives matching preorder/inorder arrays describing the same subtree. A child's `preorder[0]` is its own root, not the whole tree's root.
